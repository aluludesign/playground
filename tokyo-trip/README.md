# 東京五人行

2026/10/03 – 10/09 東京六日遊的行程、花費與分帳。

資料存在 **Notion**,網站是讀寫它的介面 —— 手機上用網站記帳,Notion 裡看表格、排序、做視圖,兩邊同一份資料。

看不需要通行碼,要動資料才需要(見「誰能改」)。

網站部署到 Vercel 後就有網址(見下方設定)。Notion 那邊不用開公開分享 ——
網站是靠 integration 的 Connections 權限讀寫的,兩者無關。

## 為什麼需要後端

Notion API 不接受瀏覽器直接呼叫(沒有 CORS),而且需要一組密鑰 —— 密鑰放前端等於公開。
所以 `api/notion.js` 這支 serverless function 擋在中間:它拿著密鑰,網站只跟它說話。

```
瀏覽器  →  /api/notion  →  Notion API
           (密鑰在這)
```

## 設定(一次性)

**1. 建 Notion integration**

到 <https://www.notion.so/my-integrations> → New integration,
取個名字(例如 `tokyo-trip`),Type 選 **Internal**,建立後複製 **Internal Integration Secret**。

**2. 把頁面分享給它**

打開 Notion 的「東京五人行」頁面 → 右上 `⋯` → **Connections** → 加入剛建的 integration。
兩個資料庫在這頁底下,會一起繼承權限。

**3. 部署到 Vercel**

<https://vercel.com> 用 GitHub 登入 → Add New Project → 選 `playground` repo。
**Root Directory 要設成 `tokyo-trip`**(不然找不到 `api/`)。

Environment Variables 加兩個:

| Name | Value |
| --- | --- |
| `NOTION_TOKEN` | 第 1 步複製的密鑰 |
| `TRIP_KEY` | 自己訂一組通行碼,給另外四個人 |

Deploy。之後每次 push 都會自動重新部署。

> `TRIP_KEY` 一定要設。沒設的話後端會拒絕所有寫入(回 503),
> 網站變成純看板 —— 這是刻意的,沒設定不等於不設防。

## 誰能改

進站時會問你走哪一條:

| | 看行程／花費／分帳 | 新增、刪除、改名字 |
| --- | --- | --- |
| **直接進入** | ✅ | ❌ |
| **管理員**(輸通行碼) | ✅ | ✅ |

通行碼對了之後這台裝置就記住了,下次直接進管理員模式;
狀態列的「登出」會忘掉它。想中途升級成管理員,按狀態列的「管理員登入」。

擋在後端:`GET` 開放,`POST`／`PATCH`／`DELETE` 一定要 `x-trip-key`。
前端把按鈕藏起來只是順手,真正說不行的是 `api/notion.js`。

**唯一的例外是許願**:`wishes` 的 `POST`（許願）和 `PATCH`（+1）不需要通行碼,
不然非管理員就許不了願。但 `DELETE`（刪掉願望）和排進行程還是要管理員,
而且沒通行碼的 `PATCH` 只改得動票數 —— 後端會把原本的標題、地點、備註讀回來蓋上去,
所以路過的人不能改掉別人願望的內容。

## 許願

行程頁最下面那塊。想去哪裡先丟進來,不用等排好:

- 誰都可以許願,也可以幫別人的願望 `+1`(再按一次取消)
- 票數多的排前面
- 管理員按願望右邊的**「加入」**,就排進**你現在看的那一天** —— 會先問你幾點,
  預設是最後一筆行程再加 30 分鐘

> 本來是長按拖到時間軸。拖曳在手機上不好按:要先長按等它浮起來,手指還不能放,
> 一路拖過整個清單。按鈕一下就好,而且看得出來它可以按。

實作上願望跟行程是**同一個 Notion 資料庫**,差別只在**有沒有填「日期」**:
沒日期 = 還在許願,填了日期 = 排進行程了。所以「排進行程」這個動作
實際上就是幫那一列補上日期和時間。

票數沒有專屬欄位(不想為了這個改 Notion 的結構),
夾在「備註」後面存成 `[+1:Chinhui,Yalun]`,網站讀出來會拆掉只顯示備註本文。
在 Notion 表格裡直接看會看到那段標記,那是正常的。

> 通行碼只是擋住路過的人,不是強加密,而且讀是公開的。
> 別把 Vercel 網址貼到公開的地方就好。

## 天氣

資料來自 [Open-Meteo](https://open-meteo.com),免費、不用金鑰,瀏覽器直接打得到,
所以不經過 `api/notion.js`。只取 ☔ 下雨機率和 🌡 白天最高溫兩項,抓回來存三小時。
離線模式也照抓 —— 它跟 Notion 無關。

數字是每次去抓的,不是寫死的。寫死的只有地點的座標(箱根永遠在那個經緯度)。
按狀態列的「重新整理」會連天氣一起重抓,不等那三小時。

- **Day 方塊**:一律顯示東京都當天的天氣
- **行程那一列**:只有**離開東京都**的地點才顯示

都內的行程不顯示是故意的:淺草、豐洲、新宿的下雨機率跟氣溫,
跟 Day 方塊上那個數字是同一個,每列重印一次只是噪音。
會不一樣的是箱根、日光、河口湖那種出東京的行程,那才印。

**預報只到今天之後 16 天。** 出發前太早看,行程那幾天根本還沒有資料,
那幾格就不顯示天氣 —— 空白是正常的,不是壞掉。大約 9/23 之後整趟都會有。

### 地點怎麼判斷

`index.html` 的 `OUTSIDE` 是一份寫死的對照表(箱根、日光、鎌倉、橫濱、川越、
輕井澤、河口湖、熱海、草津、江之島、迪士尼、成田、桃園),繁體和日文漢字都收 ——
在 Notion 打的是繁體,線上查詢服務只認日文漢字。

寫死是因為線上查詢對日文地名爛得很具體:實測「日光」給**熊本縣**的日光、
「横浜」給**青森縣**的横浜、「箱根」「輕井澤」直接查無。拿那種座標抓回來的天氣
看起來很正常,其實是九百公里外的數字 —— 比空白還糟。

表裡沒有的地點才去問線上服務,而且回來要通過檢查才採用:得落在關東到中部那個
範圍內,而且 `admin1` 不是東京都。驗不過就當作查無。**所以之後手動加的地點
走的是同一條規則,不用回來改程式** —— 只是冷門地方可能查不到,想確保有天氣,
就把它加進 `OUTSIDE`。

查過的地點(包含查不到的)都記在瀏覽器裡,不會重複問。

## 地圖

行程頁的「這天的地圖」。目的是**看各點的相對位置好排行程**,不是導航 ——
要真的帶路就點編號,跳 Google 地圖。

- 編號就是當天的順序,看得出一天怎麼走
- 顏色跟著當天的 Day 顏色
- 縮放自動抓,剛好框住當天所有的點
- **收起來時什麼都不抓**,展開才去查座標、載圖磚
- 管理員新加或改了行程,地圖跟著更新(比對的是「哪一天 + 有哪些地點」)

沒有引任何地圖函式庫。直接排 [OpenStreetMap](https://www.openstreetmap.org/copyright) 的圖磚、
投影自己算 —— 只是要看相對位置,不需要一套能拖能縮的完整地圖,
而這個專案本來就不想長出 CDN 依賴。

> 用 Google 地圖嵌入要申請 API 金鑰、綁信用卡。OSM 不用,所以走 OSM。
> 點編號跳出去的還是 Google 地圖,那個不用金鑰。

### 座標怎麼來

問 [Nominatim](https://nominatim.openstreetmap.org)(OSM 的地名查詢,免費、不用金鑰)。
它認繁體,「淺草寺」「阿美橫町」「二重橋」都查得到,比天氣用的那個準很多。

三層,由準到不準:

1. **`OUTSIDE` 對照表**(跟天氣共用)—— 箱根、日光、成田、桃園那些,座標人工確認過
2. **整串去查**,限制在大東京範圍內(`bounded=1`)
3. **去掉前面那截再查一次** —— 「銀座線 淺草站」要的是「淺草站」,
   「teamLab 澀谷 SKY」要的是「澀谷 SKY」

三層都沒有就不標,並在下面寫「有 N 個地點沒標上去」。

**日本境外的點不標。** 出發日的桃園機場查得到(對照表裡有,天氣要用),
但一張圖同時要裝下台灣和成田,就得縮到看得見鹿兒島,兩個點都被擠到邊上 ——
那張圖排行程用不到。所以 Day 1 的地圖只有成田那一個點。

**只拆一層是刻意的。** 拆到最後一段會出事:「樂桃 MM626 · 建議起飛前 2.5 小時」
會拆出「小時」,然後查到船橋市一個真的叫「小室」的地方。
`bounded=1` 也是必要的,沒有它「TPE 桃園 T1」會查到**靜岡縣**一個也叫桃園的地方 ——
點標出去看起來很正常,整張圖的比例卻毀了。

查過的地點(包含查不到的)記在瀏覽器裡,不會重複問。
Nominatim 規定每秒最多一次,所以查詢是排隊送的,地點多的那天會一個一個冒出來。

> 還是會有標錯的:「晴空塔」會查到埼玉縣一個叫「青空広場」的地方(差約 25 公里)。
> 打「東京晴空塔」就正確。地點標在奇怪的位置時,先試著把地名打完整。

存行程的當下就會查一次,查不到會在狀態列講「『XXX』查不到,地圖上不會顯示」。
不然要等你打開地圖才發現少一個點,那時候已經想不起來是哪一筆打錯了。
新增、改行程、把願望拖進行程,三個入口都會檢查。

## Icon

用 [Font Awesome Free](https://fontawesome.com/license/free) 6.7.2 的 solid 圖示(CC BY 4.0),
SVG 直接內嵌在 `index.html` 最上面的 `<symbol>` 裡,**不連 CDN** ——
在日本用手機開不用等外部資源,離線模式也照樣有圖。

要加新的 icon:去 Font Awesome 抓 solid 的 SVG,把 `viewBox` 和 `path` 複製成一個新的
`<symbol id="i-名字">`,用的地方寫 `<svg class="i"><use href="#i-名字"></use></svg>`。

## 共同基金

每人先拿 **NT$30,000** 出來（`config.js` 的 `kitty`），共同分攤的錢從這裡扣。
分帳頁最上面看得到整體用掉多少、還剩多少,以及每個人各自的進度條。

「花了多少」算的是**他分攤到的金額**,不是他掏了多少現金出來 ——
誰先墊的錢是下面「每個人的帳」在管的事,兩件事分開看。

所以只跟部分人有關的花費（例如只有兩個人合買的東西）只會扣那兩個人的額度,
其他人的不動,進度條就會長得不一樣。

超過額度的人會變紅色標「超支」。

## 名字

`index.html` 的 `MEMBERS` 每個人有兩個名字:

| 欄位 | 用途 |
| --- | --- |
| `def` | 畫面上顯示的(阿輝、佳瑜、志偉、雅倫、媽) |
| `key` | Notion「付款人／分攤者」select 的選項字串(Chinhui、Chiayu…) |

分開的原因:要改顯示名就只改 `def`,Notion 完全不用動。
如果把兩個混成一個,改名等於要去 Notion 把 select 選項和每一筆既有紀錄重設一遍。

讀回來的時候兩種都認,所以就算哪天真的在 Notion 把選項改成中文,舊紀錄也不會變成「未指定付款人」。
寫出去一律用 `key`,免得 Notion 長出第二組選項。

> Notion 裡的「同行五人」表網站不會讀 —— 那是給人看的,改那裡不會影響網站。

## 匯率

預設 **1 JPY = 0.21 TWD**,寫在 `config.js`。這是五個人共用的版本,
要改就改那裡然後 commit,同時把 Notion「花費紀錄」的「台幣金額」公式一起改掉。

## 沒設定的時候

連不上後端時網站會退回離線模式:紀錄只存在自己的瀏覽器,頁尾可以匯出／匯入 JSON。
GitHub Pages 上的那份沒有後端,永遠是離線模式。
