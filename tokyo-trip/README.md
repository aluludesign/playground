# Trippps

跟朋友一起排行程、許願、記帳分帳。**每個人都能開自己的團**(第 2 期起):
開團的人是團主,把邀請碼傳給朋友,朋友用 LINE 登入、輸入邀請碼就加入了。
**團名和產品名是兩件事**:`Trippps` 是這個網站,「東京五人行」是某一團的名字。

資料存在 **Notion**,網站是讀寫它的介面 —— 手機上用網站記帳,Notion 裡看表格、排序、做視圖,兩邊同一份資料。

**沒登入什麼都看不到,不是這一團的人連有誰都看不到**(見「誰能改」)。

網站部署到 Vercel 後就有網址(見下方設定)。Notion 那邊不用開公開分享 ——
網站是靠 integration 的 Connections 權限讀寫的,兩者無關。

### 每人最多開 2 團(2026-10-02)

30 人試用:每個人**同時**最多當 2 團的團主,**只算還沒結束的團**(網站沒有刪團;結束的也算的話開滿就永遠不能再開)。
第 3 團會回「你已經有 2 團還沒結束,等其中一團旅行結束後才能再開新的」。加入別人的團不算。
最高權限(見下)不受限。
開好團一進來,先跳「邀請好友一起來參加」(就是邀請朋友那個對話框)。驗收:`api-trip-test.js` 最後一段、`probes/new-trip-invite.js`。

### 打開就進行中的那一團(2026-10-04)

網址沒帶團代號(`?t=`)的時候 —— 最常見的是 iPhone 主畫面的 App 被系統關掉後重開,它從首頁開始 ——
**今天在旅程日期裡的團直接打開**;同時有兩團以上在進行中,先問「要開哪一團?」(只列進行中的,下面有「看全部的團」);
沒有進行中的團,照舊「我的團」清單。隱藏的團不算 —— 連最高權限自己在裡面的也不算(伺服器多給一個 `closed`:
`hidden` 是「點不進去」,對最高權限永遠是 false;`closed` 才是「真的被隱藏」),最高權限的「我的團」裡那團標「· 隱藏中」、照樣點得進去。「今天」是手機的日期。
選單的「我的團」和各處的「回我的團」都帶 `?home=1`,那時不自動開,不然一按又被開回同一團。
驗收:`probes/home-auto.js`(fixture 的 `bare=1` 和 `mytrips=`,檔頭有六種情況)。

### 小鈴鐺(2026-10-02 起全部人都有)

右上角的鈴鐺列出這一團的動態,新的在上面、沒看過的有一個點,點一則就跳過去(行程會跳到那一天):
- **誰許願**(改願望、刪願望、+1 都不通知)
- **行程**:哪一天加了/改了什麼(「時間 10:00 → 11:30」)/刪了什麼、願望排進哪一天(退回許願 = 講「刪掉了」)
- **交通異動**:加了/改了/刪了哪一段、座位
- **有新帳要分**:**只給要分的人**(「記了一筆「燒肉」¥12,000,2 人分(每人約 ¥6,000)」)
- **有新人加入**:全部人都看得到;「座位多了他的空格 / 去填座位」只給團主和副團主
- **自己做的不通知自己**。打開鈴鐺 = 看過了(記在成員表的「通知已讀」,換手機不會再亮)。

動態存在 Notion 新表「動態」(`NOTION_DB_ACTIVITY`,預設 ee00c7c3…),伺服器每存一次行程/帳/交通/許願就寫一列;
**寫不進去不會讓存檔失敗**。`GET resource=activity&t=` 只回給你看的(濾掉自己的、不是給你的帳,也不回「給誰」)。
驗收:`api-trip-test.js` 的「小鈴鐺的動態」、`probes/bell.js`(`?feed=1`、`?newbie=1&fake=member`…)。

## 為什麼需要後端

Notion API 不接受瀏覽器直接呼叫(沒有 CORS),而且需要一組密鑰 —— 密鑰放前端等於公開。
所以 `api/notion.js` 這支 serverless function 擋在中間:它拿著密鑰,網站只跟它說話。

```
瀏覽器  →  /api/notion  →  Notion API
           (密鑰在這)
```

## 設定(一次性)

**1. 建 Notion integration**

到 <https://www.notion.so/my-integrations> → New integration,
取個名字(例如 `tokyo-trip`),Type 選 **Internal**,建立後複製 **Internal Integration Secret**。

**2. 把頁面分享給它**

打開 Notion 的「**Trippps**」頁面 → 右上 `⋯` → **Connections** → 加入剛建的 integration。
資料庫都在這頁底下,會一起繼承權限 —— **加在頁上,不要一張一張加**,
不然以後新增的表不會自動涵蓋到,而症狀看起來只是「那張表是空的」。

**3. 部署到 Vercel**

<https://vercel.com> 用 GitHub 登入 → Add New Project → 選 `playground` repo。
**Root Directory 要設成 `tokyo-trip`**(不然找不到 `api/`)。

Environment Variables 加這幾個:

| Name | Value | |
| --- | --- | --- |
| `NOTION_TOKEN` | 第 1 步複製的密鑰 | 必要 |
| `GEOCODE_KEY` | 地名查詢退路的金鑰 | 選填,見「[標錯了怎麼辦](#標錯了怎麼辦再查一次)」 |
| `GEMINI_KEY` | Google AI Studio 的 API 金鑰 | 選填,見「[AI 按鈕](#ai-按鈕)」 |
| `LINE_CHANNEL_SECRET` | LINE Login channel 的密鑰 | **必要**(第 2 期起沒登入什麼都看不到),見「[用 LINE 登入](#用-line-登入)」。Production 和 Preview 都要勾 |
| `LOGIN_HOST` | 登入網域,不設就是正式站 | 選填,見「[用 LINE 登入](#用-line-登入)」 |
| `TRIP_MAX_PEOPLE` | 試用名額,不設就是 30 | 選填,見「[誰能改](#誰能改)」 |

Deploy。之後每次 push 都會自動重新部署。

**網址是這個 —— 要給那四個人的就是它:**

<https://playground-beta-liart.vercel.app>

> **只有這一個網址是公開的。** Vercel 另外會生一些別名(`playground-lulu-6af6.vercel.app`、
> `playground-git-main-lulu-6af6.vercel.app`…),那些被 Standard Protection 擋著,
> 打開會轉去 Vercel 登入 —— **那是預設行為,不是站掛了**。
>
> 要確認站活著,打正式網址,不要打別名。在 Vercel 的 Environments → Production → Domains
> 那一列,第一個就是正式網域,後面收在 `+2` 裡的才是別名。
>
> (這件事害兩個人各花了半小時以為使用者全被鎖在外面。網址寫在這裡就是為了不要有第三次。)

> **`GEOCODE_KEY` 不設也沒關係**,網站其他部分完全照常,只有地圖上那顆
> 「再查一次」按下去會說「伺服器還沒設定 `GEOCODE_KEY`」。
> 它要的是 Google Cloud 的 **Geocoding API** 金鑰(Google Cloud Console →
> APIs & Services → 啟用 Geocoding API → Credentials → Create credentials → API key)。
>
> **這把金鑰只能放在 Vercel 的環境變數裡**,理由跟 `NOTION_TOKEN` 一模一樣:
> 放進網頁就是公開。程式只從 `process.env.GEOCODE_KEY` 讀,前端一個字都拿不到。
> 建這把金鑰的時候順手在 Google Cloud 那邊做兩件事:
> **Application restrictions 選 None(呼叫的是伺服器,不是瀏覽器)**、
> **API restrictions 只勾 Geocoding API**,再設一個每日用量上限 ——
> 這條退路是人按一下才查一次,正常一天不會有幾筆。

## 用 LINE 登入

**第 2 期起,登入是進門的唯一一條路。** 以前是「讀公開、寫要通行碼」,LINE 只回答「你是誰」;
現在每一團只有自己的成員看得到(Lulu 2026-09-26),通行碼拿掉了。

設定要做三件,缺一件登入就是不會動:

1. <https://developers.line.biz/console/> 建一個 **LINE Login channel**,
   **Callback URL 填 `https://playground-beta-liart.vercel.app/api/auth`** ——
   LINE 會逐字比對,差一個斜線就會說 `redirect_uri` 不符。**只要這一行**,見下面「preview 怎麼登入」。
2. 把 **Channel secret** 貼進 Vercel 的 `LINE_CHANNEL_SECRET`,**Production 和 Preview 都要勾**。
   **只能放那裡**,理由跟 `NOTION_TOKEN` 一樣:放進網頁就是公開。
   > **環境變數只給之後的部署** —— 改完要 Redeploy,否則那一版照舊回「還沒設定」。
   > 症狀會騙人:開到舊的部署網址,看起來就像設定沒存進去。
3. 把 channel 從 **Developing 切成 Published**。
   > 這一個最容易漏,而且症狀會騙人:**開發中的狀態只有 channel 的擁有者登得進去**,
   > 所以你自己測一切正常,別人按下去看到的是登不了。

沒設 `LINE_CHANNEL_SECRET` 的話,後端會直說「還沒設定」而不是「登入失敗」——
後者會讓人一直重試一顆永遠不會成功的按鈕。

其他欄位不用動。**Assertion Signing Key 不要註冊** —— 那是「不想用 channel secret」
的替代做法,註冊了就多一把私鑰要保管,而我們用不到。

### preview 怎麼登入(不用再去 LINE 加網址)

以前每開一個分支,就要去 LINE 後台多登記一行 `playground-git-<分支>-…/api/auth`。
現在 **LINE 一律回到正式站**:

1. 在 preview 按登入 → `state` 裡簽著「從哪個網域出發、出發時那串亂數」→ 去 LINE
2. LINE 回到正式站 → 正式站驗完身分,**發一張 60 秒的票**,把人送回那個 preview 的 `/api/auth?go=take`
3. preview 收票:網域是自己、沒過期、亂數跟出發時存在這台瀏覽器的 cookie 一樣 —— 三件都對才發身分

票只送去白名單裡的網域(正式站、`playground-*-lulu-6af6.vercel.app`),不然就是
「LINE 登入完把你的身分送給任何網站」。

> **這一套要正式站那邊先有新的 `api/auth.js`。** preview 借的是正式站的回呼,
> 正式站還跑舊版的話,preview 登入會停在正式站首頁。

### iPhone 主畫面 App

主畫面 App 有自己的 cookie 倉庫,而且一導覽到站外(LINE)就被踢到瀏覽器 ——
登入在瀏覽器裡成功,App 裡還是沒登入。所以 App 裡的登入是兩步:

1. App 裡按「用 LINE 登入」→ 另開瀏覽器登入
2. 登入完那一頁印一組 **8 碼的登入碼**(10 分鐘內有效、只能用一次),回 App 貼上

碼存在「人」那張表的 `登入碼` / `登入碼到期`。偵測不到是 App 的時候(有些裝置不給),
登入卡上的「我有登入碼」還是走得到同一條路。

**App 裡的登入卡寫成兩步**(2026-10-14,Lulu 問「還沒登入時把登入碼欄和登入鈕 disable 會怎樣」):不能 disable ——
App 看不到你在瀏覽器那邊登入了沒(兩邊的登入是分開存的),關掉就永遠打不開;「在 App 裡按過 LINE 登入才打開」也不行
(iPhone 切去瀏覽器時常把 App 關掉重開,記錄會不見;也有人自己開瀏覽器登入)。所以改成:卡上寫「① 用 LINE 登入」「② 回來貼上登入碼」,
輸入框一直能打字,**只有「登入」鈕在湊滿 8 個英文或數字前是灰的**(- 和空白不算、大小寫都行);輸入框 maxlength 放寬到 20,貼上多帶的空白不會把碼切掉。
一般瀏覽器那張卡照舊(「我有登入碼」打開才看得到),登入鈕一樣湊滿才亮。驗收:`probes/appcode.js`(`fake=app`、`fake=anon`)。

驗收在 `adopt-harness/api-auth-test.js`(伺服器那半:簽章、state、逾時)
和 `adopt-harness/probes/line-login.js`(畫面那半:按鈕在不在、按下去會不會真的走)。

## 誰能改

**「你是誰」和「你能改什麼」是兩件事。**

| | 回答什麼 | 怎麼來的 |
| --- | --- | --- |
| LINE 登入 | 你是誰 | 簽章過的 cookie,前端偽造不了 |
| 成員 | 你在這一團是哪一個人 | Notion「成員」表(加入的那一刻就綁定 LINE) |
| 角色 | 你動得了哪一塊 | 「成員」的角色(團主/副團主/成員)+「團」的「副團主可管…」三個 checkbox |

判準(全部擋在 `api/notion.js`,前端藏按鈕只是順手):

- **沒登入** —— 什麼都讀不到。
- **不是這一團的人** —— 連有誰都讀不到。要有邀請碼才能加入。
- **團主**(開團的人) —— 什麼都能改,也只有團主能改團的設定。
- **副團主**(2026-10-01 起)—— 一團 1 位,**只有團主能指派**。能動哪幾塊看團主勾了哪些:
  `副團主可管行程` / `副團主可管記帳` / `副團主可管交通`(交通和座位),預設都關著。
  **每天只能換一次**(一天 = 台灣 15:00 到隔天 15:00,換人和取消都算;第一次指派不算),
  擋住一直換人刷 AI 的 +5。換上來的人權限馬上生效,換下去的人馬上變回一般成員。
  換的時間記在「團」表的「副團主換人時間」。
- **團結束之後**(2026-10-01)—— 照旅遊當地時間(日本的團照日本時間、台灣的團照台灣時間),
  最後一天 23:59 一過就結束,不需要誰去按:行程、交通、許願、投票全部鎖住,AI 按鈕對所有人消失
  (伺服器也擋);**團主和團主勾了記帳的副團主還能記帳、改花費**,一般成員只能看。團不會再打開。
  旅程開始之後第一天不能改、最後一天只能往後延;結束之後日期不能再改。
  (驗收:`api-trip-test.js` 的「團的生命週期」、`probes/trip-ended.js`)
- **一般成員** —— **只能許願**。以前「團」表那三個整團一起開的開關(`成員可管…`)不再用。
- **許願** —— 成員都能許、都能 `+1`,不用開關。「誰許的」和「誰按的 +1」由伺服器認人,
  前端送什麼都不算數;改內容和刪掉要是許願的人、團主、或有管行程權限的人。
- **改和刪都先確認那一筆是這一團、這張表的。** 只有 id 不夠 —— 拿得到別團某一筆 id 的人
  以前改得動別人的帳。

**畫面跟伺服器一塊一塊對齊**:只勾「記帳」的話,副團主看得到「記一筆」和花費的「改」,
但看不到「加行程」和「加一段交通」。**看得到的按鈕就按得動** —— 讓人按了才被拒絕,比讓他看不到更糟。
(驗收:`PAGE='/index.html?fake=member&can=cost' ./probe.sh probes/toggles.js` —— fixture 裡帶 `can=` 的成員就是副團主;
`probes/deputy-quota.js` 問指派、換人、今天鎖住)

**測試環境的「用成員身分看」**:在 preview(不是正式站),團主的選單裡多一顆「用成員身分看(測試)」。
按下去之後**伺服器也把你當一般成員**(只能許願),不只是畫面換個樣子 —— 測得到真的權限規則。
頂列上、漢堡選單左邊(手機是分頁列正上方)會一直掛著「測試:成員 · 切回團主」,按它就切回來。
- **只能降級**:成員帶同一張 cookie(`trip_as=member`)什麼都不會變。
- **正式站整個不理它**:靠 Vercel 的 `VERCEL_ENV=production`,切換鈕也不會畫出來。
(驗收:`api-trip-test.js` 的那一段、`probes/viewas.js`、`PAGE='/index.html?prod=1'` 那一次)

**邀請碼是每個人各一組**:朋友用誰的碼加入,就記下是誰邀請的;在「邀請朋友」按「換一組」,
舊的碼就不能用了(已經加入的人不受影響)—— 想斷掉某一條擴散線就換那個人的碼。

**試用名額**:`人` 那張表滿 `TRIP_MAX_PEOPLE`(預設 30)之後,新的人登入會被擋在
LINE 回來那一步,看到「試用名額目前滿了」。**來過的人不佔新名額**,滿了照樣進得來。
Notion 那邊出事的時候**放行**,不是把所有人鎖在外面 —— 那張表是數人頭用的,
不是安全邊界(安全邊界是 cookie 和「成員」表)。

### 刪東西前再問一次(2026-10-03)

行程的 ✕、願望左滑的「刪除」、花費的「刪除」(還沒送出的是「取消這筆」)、交通的「刪掉這一段」,
按下去都先跳 App 自己的確認對話框,講出要刪的是哪一筆(行程帶日期、願望帶票數、花費帶金額、交通帶座位)。

## 天氣

資料來自 [Open-Meteo](https://open-meteo.com),免費、不用金鑰,瀏覽器直接打得到,
所以不經過 `api/notion.js`。只取 ☔ 下雨機率和 🌡 白天最高溫兩項,抓回來存三小時。
離線模式也照抓 —— 它跟 Notion 無關。

數字是每次去抓的,不是寫死的。寫死的只有地點的座標(箱根永遠在那個經緯度)。
按狀態列的「重新整理」會連天氣一起重抓,不等那三小時。

**降雨和氣溫要兩個都有才顯示。** Open-Meteo 的降雨機率比氣溫多預報一天,
邊界那天只給得出一半 —— 印出「☔ 32%」旁邊空一塊看起來像壞掉,而那天是預報最遠、
最不準的一天,隔天就補齊了。

- **Day 方塊**:一律顯示東京都當天的天氣
- **行程那一列**:只有**離開東京都**的地點才顯示

都內的行程不顯示是故意的:淺草、豐洲、新宿的下雨機率跟氣溫,
跟 Day 方塊上那個數字是同一個,每列重印一次只是噪音。
會不一樣的是箱根、日光、河口湖那種出東京的行程,那才印。

**預報只到今天之後 16 天。** 出發前太早看,行程那幾天根本還沒有資料,
那幾格就不顯示天氣 —— 空白是正常的,不是壞掉。大約 9/23 之後整趟都會有。

### 強力搜 = Google 的 Places UI Kit 清單(2026-10-02)

搜尋鈕第 3 段「強力搜」改成 Google 的 **Places UI Kit**(Place Search 元件)清單 —— 為了 Google 的條款
(Google 的資料畫在非 Google 地圖上只允許用 UI Kit,§15.1)。地圖照舊是 OpenStreetMap,第 1、2 段照舊是免費的 Nominatim。

- **瀏覽器金鑰**:Vercel 的 `GOOGLE_MAPS_BROWSER_KEY`(Production 和 Preview 都要),由 `api/notion.js?resource=mapskey` 轉交(要登入)。
  它本來就是公開的,靠 Google Cloud 的網址白名單保護。**沒設、或 8 秒內載不到,就說「清單載入出現錯誤」**,叫人稍後或重開再試(這一下不扣次數;對使用者不講免費不免費)。
- 清單是**橫式**(`orientation="horizontal"`),有照片;直式的清單 Google 不給照片(用 Google 自己的範例頁確認過)。
- 挑一家:名字、地址、座標記在這台手機(`tokyo5-pin3`,帶 `pid` 地點編號和 `t` 挑的時間);**地點編號**跟著行程／願望存進 Notion
  「行程」表的「地點編號」欄。座標不進 Notion(條款:最多 30 天)。地圖上的點點過去用編號開 Google 地圖,一定是挑的那一間。
- 1 次 = 按一次強力搜、出一份清單(照片包含在內)。Google Cloud 那邊設了每天 300 次上限。
- **每人每天的次數**:一般成員 8 次,團主和副團主 12 次,參加的團共用;跟 AI 一樣照 Google 的一天(台灣下午 3 點/4 點重算)。
  記在「AI 用量」表,`模型` 寫 `強力搜:<LINE 編號>`。按下去先 `POST /api/ai?strong=1` 記一次,用完回 429(對使用者只講用完、幾點重算)。
  漢堡選單「今天的 AI」下面寫「強力搜:還能用 N／M 次」,強力搜那句提示旁邊也寫。
  **清單出錯(`gmp-error`:斷線、Google 故障、全站 300 次到頂)會退回那一次**:記一次時伺服器給一張收據(綁誰、哪天、第幾次),
  `POST /api/ai?strong=1&refund=1` 帶收據退;退過就對不上,不能一張退很多次。元件根本載不出來的話一開始就不扣。
- 舊的伺服器強力搜(`resource=places`/`placephoto`/`geocode`)已拿掉,**`GEOCODE_KEY` 不再需要**,可以從 Vercel 刪掉、在 Google Cloud 停用那把金鑰。
- 還沒做(第 ② 步):30 天到期後改用免費搜尋按名字查、查不到在那一列提示「地圖上沒有位置 · 重新挑一次」。
- 驗收:`probes/uikit.js`(假的同名元件)、`PAGE='/index.html?nouikit=1'`(載不出來)、`?strong=0/8`(用完)、`api-usage-test.js` 的強力搜那段、`api-trip-test.js` 的 UI Kit 那段。

### 地點怎麼判斷

`index.html` 的 `OUTSIDE` 是一份寫死的對照表(箱根、日光、鎌倉、橫濱、川越、
輕井澤、河口湖、熱海、草津、江之島、迪士尼、成田、桃園),繁體和日文漢字都收 ——
在 Notion 打的是繁體,線上查詢服務只認日文漢字。

寫死是因為線上查詢對日文地名爛得很具體:實測「日光」給**熊本縣**的日光、
「横浜」給**青森縣**的横浜、「箱根」「輕井澤」直接查無。拿那種座標抓回來的天氣
看起來很正常,其實是九百公里外的數字 —— 比空白還糟。

表裡沒有的地點才去問線上服務,而且回來要通過檢查才採用:得落在關東到中部那個
範圍內,而且 `admin1` 不是東京都。驗不過就當作查無。**所以之後手動加的地點
走的是同一條規則,不用回來改程式** —— 只是冷門地方可能查不到,想確保有天氣,
就把它加進 `OUTSIDE`。

查過的地點(包含查不到的)都記在瀏覽器裡,不會重複問。

## 地圖

**一張地圖,兩種內容。** 手機從底部滑上來,桌機從右邊變抽屜,兩個入口開的是同一張:

地圖上方有三顆開關。行程和願望兩種點**畫得一樣明顯,靠顏色分**:

| 圖層 | 顏色 | 編號 |
| --- | --- | --- |
| **Day n**(選著的那一天) | 那一天的 Day 顏色 | 當天的順序 |
| **不分天數**(六天全部) | 各自那一天的 Day 顏色 | 第幾天 |
| **大家的許願** | 主色 | 清單上的編號 |

**顏色由「它是什麼」決定,不是由「你在看哪張圖」決定。** DAY 3 的淺草寺在哪張圖上
都是綠的,願望在哪張圖上都是主色。所以每個點都寫死自己的顏色,不去繼承容器的
`--dc` —— 靠繼承的話,同一個願望在行程地圖裡會變成那天的顏色。

第一顆的名字跟著選著的那一天換(`Day 1`、`Day 2`…),**只放那一天的行程**,
行程頁、許願頁都一樣。在許願頁切日子,地圖也跟著換成那天的行程。

每一頁有一顆**鎖著開**,按了沒反應;其他的可以自己開關:

| 分頁 | 鎖著開 | 可以開關 | 一進來 |
| --- | --- | --- | --- |
| 行程 | Day n | 大家的許願、不分天數 | 願望關、不分天數關 |
| 許願 | 大家的許願 | Day n、不分天數 | Day n 開、不分天數關 |

換分頁的那一下回到上表的「一進來」;同一頁裡手動開的,換天不會被關回去。

**「不分天數」跟 Day n 互斥。** 開了它,地圖改放六天全部的行程,Day n 變成停用
(淡掉、按不動)。關掉它就回到 Day n 原本的樣子。下面這些動作會自動把它關掉 ——
你指著某一天的某個點,地圖就不該還在講六天全部:

- 點行程那一列、點願望卡片(會把地圖移到那個點的動作)
- 點上面的日子(不然切日子地圖不會動)

取景跟著「大家的許願」走:

- **願望開著** → 所有願望都框得進來,當天的行程也一起框。不排除離很遠的點 ——
  「全部的願望都看得到」就是這條規則本身
- **願望關著** → 只框當天的行程(離很遠的那一個照下面的規則排除)

手機上清單 sheet 蓋住地圖下半部,取景和聚焦都只算**露出來的那一塊**,
點不會落在 sheet 後面。

地圖入口每天都在同一個位置 —— 標題列最右邊那一顆,不用找。

目的是**看各點的相對位置好排行程**,不是導航 —— 要真的帶路就點編號,跳 Google 地圖。

許願池那張不是固定在頁面上的:它是看一眼就收起來的東西,不該長期佔著清單的位置。
**手機**從底部滑上來,**桌機(≥641px)**從右邊滑進來變成抽屜。
按 ✕ 或 Esc 收起來;收起來就不再抓任何東西。

抽屜打開時,**左邊的版面是縮到剩下的寬度重排,不是被蓋住**。
左邊緣那條握把可以拖著拉寬,寬度只有四檔 —— 螢幕的 1/4、2/4、3/4、4/4,
放開會吸到最近那一檔。存的是「第幾檔」不是像素,換螢幕、轉方向都還是同一個比例。

**背景不變暗、不模糊,而且照樣點得到。** 開著地圖還要能捲願望清單來對照,
那才是它存在的理由 —— 所以外層容器 `pointer-events:none`,只有卡片本身收事件。
代價是沒有「點背景關閉」這件事,收起來只能按 ✕(或桌機按 Esc)。
沒填地點的願望標不出來,所以清單上也不給它編號 —— 不然編號會跳號、對不起來。

- 編號就是當天的順序,看得出一天怎麼走
- 顏色跟著當天的 Day 顏色
- **拖得動、捏得大**,也有雙擊放大和角落的 `+` `−`;點標記開 Google 地圖
- 預設視角自動框好,**收起來時什麼都不抓**,打開才去查座標、載圖磚
- 管理員新加或改了行程,地圖跟著更新(比對的是「哪一天 + 有哪些地點」)

每個標記正上方掛著**「做什麼／想去哪」那欄填的字**,小小一片。

標籤會互相蓋住,所以畫完之後會**自動讓位**:照優先序一片一片放(願望先、行程後),
位置被佔走就改放到標記下面,下面也被佔走就先藏起來 ——
藏起來的滑過或被聚焦時照樣冒出來,不是永久消失。

**桌機**的 hover 是雙向的:滑過清單那一列,地圖上對應的標記跳出來;
滑過地圖上的標記,清單那一列也亮起來 ——
許願地圖開著的時候滑過行程列,亮的是它那顆「已排」的背景標記。
手機沒有 hover 這回事(碰一下就等於點下去),所以只在有指標的裝置上裝。

**時間軸每一列前面的號碼牌,就是地圖上的那個標記** —— 同一個編號、同一個樣式,
所以兩邊看起來是同一個東西。點那一列,地圖會打開並移到那個點,標記和列一起亮起來。
許願清單也一樣。

聚焦在某一個點的時候:

- **開「大家的許願」** → 取景縮到所有願望都看得到,那個點**照樣亮著**
- **再關掉** → 回到那個點的特寫
- **再點一次那一列,或再點一次已經選著的那一天** → 退出聚焦,回到那天的整體視野
- 換到別天 → 聚焦清掉(別天的第 2 個不是同一個地方)

編號要對得起來,時間軸和地圖就得用同一份清單、同一個排序(`dayList()`)——
各排各的話,同一分鐘的兩筆會因為排序穩定性而錯位。

願望關著的時候,預設的縮放只遷就**多數點所在的那一區**(取中位數當中心,60 公里內算同一區)。
一個輕井澤就能把整張圖縮到看得見群馬,東京那幾個點全擠成一團 ——
而那團正是你要看的。離群的點照樣畫,但通常落在畫面外,所以說明裡會點名:
「3 輕井澤(約 128 公里外)離得遠,要拖出去才看得到」。

沒有引任何地圖函式庫。直接排 [OpenStreetMap](https://www.openstreetmap.org/copyright) 的圖磚、
投影自己算 —— 只是要看相對位置,不需要一套能拖能縮的完整地圖,
而這個專案本來就不想長出 CDN 依賴。

> 用 Google 地圖嵌入要申請 API 金鑰、綁信用卡。OSM 不用,所以走 OSM。
> 點編號跳出去的還是 Google 地圖,那個不用金鑰。

### 這趟在哪個國家

看**網頁標題**決定。`index.html` 的 `REGIONS` 是一小張表:標題裡出現「東京」就查日本、
出現「首爾」就查韓國,依此類推。認不出來就當東京。

它管兩件事:地名查詢限制在哪個國家、偏重哪一塊範圍。
所以把 `<title>` 裡的團名從「東京五人行」改成「大阪京都自由行」,查詢範圍自己就跟著換,
不用去翻程式碼裡的座標。表裡沒有的城市,加一行就好。

> **`<title>` 現在是「團名 · Trippps」,團名那一半是有作用的,不要拿掉。**
> 多租戶之後這件事會搬進「團」的資料裡(一團一個地區),到那時候標題才真的只是標題。

### 點標記開 Google 地圖

**連結會帶上座標。** 只丟名字過去的話,Google 會用「你人在哪」來猜 ——
在台灣點「輕井澤」會跑出一堆台灣的火鍋店。座標我們查地名時就已經知道了,
把地圖中心一起帶過去(`/@36.342,138.629,14z`),它就只會在那附近找。

### 座標怎麼來

問 [Nominatim](https://nominatim.openstreetmap.org)(OSM 的地名查詢,免費、不用金鑰)。
它認繁體,「淺草寺」「阿美橫町」「二重橋」都查得到,比天氣用的那個準很多。

先拿「地點」欄查,查不到就拿**「做什麼／想去哪」那欄再查一次**。
地點欄常常沒填,或填的不是地名(實際資料裡有一筆填「🦞」),
而標題往往本身就是地名 —— 淺草寺、合羽橋道具街、築地市場、夢の島熱帯植物館。

每個字串都走同樣三層,由準到不準:

1. **`OUTSIDE` 對照表**(跟天氣共用)—— 箱根、日光、成田、桃園那些,座標人工確認過
2. **整串去查**,限制在一塊範圍內(`bounded=1`)—— 哪一塊看字串自己講的是哪裡
3. **去掉前面那截再查一次** —— 「銀座線 淺草站」要的是「淺草站」,
   「teamLab 澀谷 SKY」要的是「澀谷 SKY」

都沒有就不標,並在下面寫「有 N 個沒標上去」。像「泡溫泉」這種本來就不是地名的,
標不出來是正確的。

**日本境外的點不標。** 出發日的桃園機場查得到(對照表裡有,天氣要用),
但一張圖同時要裝下台灣和成田,就得縮到看得見鹿兒島,兩個點都被擠到邊上 ——
那張圖排行程用不到。所以 Day 1 的地圖只有成田那一個點。

**只拆一層是刻意的。** 拆到最後一段會出事:「樂桃 MM626 · 建議起飛前 2.5 小時」
會拆出「小時」,然後查到船橋市一個真的叫「小室」的地方。

**界線是必要的,但不該一律用這趟的城市。**

`bounded=1` 的意思是「框外的一律不算」。少了它,不是地名的字串在全日本一定找得到
「某個」東西 —— 「泡溫泉」會給鳥取的吉方温泉通り,「港灣未來」會給福井的勝山丸岡線。
標出去看起來很正常,其實差了四百公里。

但把框鎖死在這趟的城市也不行,那樣 Nominatim 只好從框內硬挑一個最像的交差:

| 你打的 | 鎖死在東京框裡給你的 |
| --- | --- |
| 京都車站 | 東京車站大飯店 |
| 伏見稻荷 | 荒川區一個同名小社 |
| 金閣寺 | 埼玉的日立金屬熊谷工場 |

名字對不上也照給,而且每筆挑到的還不一樣 —— 加兩個京都的地點,會落在東京兩個
不相干的位置上。

所以框還在,只是**看字串自己講的是哪裡**(`regionFor`):東京行裡的「新宿」還是在
東京找,「京都車站」會去關西找。`REGIONS` 的順序有意義 —— 東京排第一,「東京都廳」
才不會被中間那兩個字拐去京都。

想要哪一個,就把地名打完整:東京行打「清水寺」會給橫濱那間,要京都的打「京都 清水寺」。
離群的點照樣標,取景只遷就多數點所在的那一區,所以一個京都的點不會把整張圖縮掉。

查過的地點(包含查不到的)記在瀏覽器裡,不會重複問。
Nominatim 規定每秒最多一次,所以查詢是排隊送的,地點多的那天會一個一個冒出來。

> 還是會有標錯的:「晴空塔」會查到埼玉縣一個叫「青空広場」的地方(差約 25 公里)。
> 打「東京晴空塔」就正確。地點標在奇怪的位置時,先試著把地名打完整。

存行程的當下就會查一次,查不到會在狀態列講
「『XXX』查不到 —— 試試把地名打完整,或開地圖點那一列再查一次」。
不然要等你打開地圖才發現少一個點,那時候已經想不起來是哪一筆打錯了。
新增、改行程、把願望拖進行程,三個入口都會檢查。

### 標錯了怎麼辦:再查一次

**線上查詢不確定的時候不會說。** 同一份格式、同樣的欄位:

| 你打的 | 回來的 | |
| --- | --- | --- |
| 淺草寺 | 35.7134,139.7955 · 淺草寺, 浅草二丁目, 臺東區, 東京都 | 對 |
| 泡溫泉 | 24.6985,99.6963 · 温泉镇, 保山市, 云南省, 中国 | 錯,差三千公里 |

沒有信心值、沒有警告,所以程式無從判斷第二筆是錯的,
畫出來的是一顆**很有自信的錯 pin**。

**但你看得出來。** 打「泡溫泉」的人知道那不是地名,看到 pin 跑到雲南的人也知道不對。
所以這件事不交給程式偵測,交給你按一下:

1. 在時間軸或許願清單上**點那一列**(本來就會打開地圖並移到那個點)
2. 地圖上方多出一條:「『淺草寺』不在這裡?」或「『泡溫泉』沒標上去」
3. 按**「再查一次」**

換一家查。那一家查得到的東西不一樣,而且**會講它有多確定**:

| 結果 | 你會看到 |
| --- | --- |
| 查到精確位置 | pin 換到新的地方,狀態列說「重新標好了」 |
| 查出來跟原本同一個位置 | 狀態列說「再查一次還是同一個位置」——**不會假裝有進展** |
| 只查到大概的範圍 | 照樣標,但那顆 pin 畫成**虛線圈**、標籤前面加「約 」,狀態列提醒把地名打完整 |
| 還是找不到 | 狀態列說「還是找不到 —— 它可能不是一個地名」,地圖上維持沒有那個點 |

**「約 」那一種要特別講。** 有些字串只查得到行政區級的答案 ——
例如「東京都廳」可能只回「日本東京都」,座標是整個東京都的概略中心。
那顆 pin 看起來跟精確的一模一樣,所以它被畫成虛線的,免得你拿它排行程。
**想要精確的,把地名打完整再查一次**(「東京都廳舍」「新宿 東京都廳」)。

修好的座標**蓋掉舊的那一筆**,存在同一個地方(這台裝置的瀏覽器),
下次打開還是修好的。但**只在按下去的那台裝置上** —— 座標沒有存回 Notion,
別人的手機還是舊的。

> 強力搜會花錢(見上面「強力搜 = Google 的 Places UI Kit 清單」)。**沒有人按,就一次查詢都不會發出去。**

## AI 按鈕

### 每個人每天幾次(2026-10-01)

- **一般成員每天 20 次,團主和副團主 25 次。** 一個人參加好幾團也是同一份(各團共用),身分取高的那個。
- **成功拿到結果才扣一次**;失敗、打開對話框、按確定存都不扣。用完了就不去問 Google。
- 一天照 Google 算:太平洋時間午夜 = 台灣**下午 3 點**(冬令 4 點)重算。
- 剩幾次講在**個人漢堡選單**最上面和 **AI 對話框**裡;用完時寫「你的 AI 額度用完了,下午三點後再用」。
- 記在 Notion(Trippps 底下):**「AI 紀錄」**每按一次一列(時間、哪一團、誰、身分、AI 讀出的類型、成功/失敗/次數用完、模型、實際打了幾次 Google)——
  **不記打的字和圖片**;今天用了幾次就是數這張表。**「AI 用量」**每天每個模型一列(成功幾次、實際打了幾次、Google 說用完了沒)。
- 這兩張表讀不到的時候,AI 照常能用(不擋、也不講剩幾次)。數字寫在 `api/_usage.js` 的 `LIMIT`。

頂列右上的 **✨ AI**。打一段話、加一張圖(或兩個都有),AI 判斷要建哪一種資料:

| 你說/你給 | 會建 | 誰能用 |
| --- | --- | --- |
| 「這家想去,許願」+ Google 地圖截圖 | 許願一筆 | 所有人 |
| 「加到第 3 天晚上 7 點」+ 訂位確認 | 那一天的行程一筆 | 團主、有管行程權限的人 |
| 座位表、登機證、選位畫面 | 搭機頁的座位(那一班要先加進航班) | 團主、有管機位權限的人 |

- **一定先跳確認卡,按「確定」才存。** 卡上每一欄都能改,包括「加到哪裡」——
  AI 看錯類型,換一下就好。存的時候走的是手動加的同一條路,權限也一樣。
- **地點還是人挑。** 有地名的話確認卡會先幫忙搜一次,挑了才上地圖;不挑照樣存,只是不上地圖。
- **花費還不做**(2026/09 決定)。
- **用的是 Gemini API 免費方案**:依序試 `gemini-3.5-flash-lite` → `gemini-3.1-flash-lite` → `gemini-3.8-flash`,
  前一個額度用完才換。2026/09 在 AI Studio 看到的免費額度:Flash-Lite 每天 500 次、Flash 每天 20 次。
- **免費方案的內容會被 Google 用來改善產品**(官方價目表寫的)。訂位確認和座位表上有姓名,五個人要知道。
- **`/api/ai` 要登入才能用**,不然知道網址的人就能用掉免費額度。它只看有沒有登入、不看在哪一團 —— 存資料的那一步照樣走 `api/notion.js` 的權限。
- 圖片先在瀏覽器縮到長邊 1600px 的 JPEG 才上傳。

### 座位存在哪

Notion「Trippps」底下的 **座位** 資料庫:一列 = 一個人在一段交通上的位子(航班、日期、旅客、座位)。「航班」欄對的是那一段的班次;沒有班次的巴士、船用那一列自己的代號。

**航班** 資料庫(2026-09-28 起不只飛機):多了「種類」(飛機/火車/巴士/船/租車,空白 = 飛機)、「訂位代號」、「駕駛」(租車,成員代號用逗號分開)。其他欄位照舊,只是換個意思:航班號 = 班次/車次、航空公司 = 哪一家、起飛/抵達 = 出發/抵達(租車是取車/還車)。
2026-10-12 起「種類」多一個**通票**:航班號 = 票名、起飛/抵達 = 第一天/最後一天(**只有日期**)、駕駛 = 誰有這張(可以不勾)、起飛機場/抵達機場留空。第一次存通票時 Notion 會自己長出「通票」這個選項。
用航班號當標題,不是「去程/回程」—— 之後航班不會只有兩班。
`index.html` 的 `FLIGHTS` 決定這一趟把哪一班畫在去程、哪一班畫在回程;不在 `FLIGHTS` 裡的航班先不畫。
程式裡的 `SEATS` 是讀不到資料庫時的備援。

## 輸入框裡的網址

備註、名稱、地點這些欄位打進去的文字,只要含 `http://` 或 `https://` 就會變成可以點的連結,
**底下畫虛線**表示它是連結,點了開新分頁。顏色跟本文一樣,不搶戲。

結尾的標點不算網址的一部分 —— 「詳見 https://x.com/a。」那個句號是中文句號,不是網址。

### 從網頁複製過來的連結

從網頁複製一段字,連結是藏在**格式**裡的。`<input>` 只收純文字,貼進去的當下那個網址
就沒了,只剩看得見的字 —— 所以網站自己接 `paste`:剪貼簿裡有 HTML 就把 `<a>` 抽出來,
寫成 `[文字](網址)` 存進欄位,顯示時再變回可以點的連結,**看到的還是原本那幾個字**。

例如從 Google 地圖複製「豐洲市場」,欄位裡會是:

```
[豐洲市場](https://maps.app.goo.gl/xyz)
```

畫面上顯示的是「豐洲市場」,點了開 Google 地圖。

> 代價是**編輯的時候會看到那串標記**。Notion 的欄位是純文字,`<input>` 也存不了格式,
> 要留住網址就得把它寫進文字裡 —— 跟票數存成 `[+1:...]` 是同一套做法。
> 不想要就把那串刪掉,或直接貼純文字。

## 版面寬度

**最寬就是螢幕,不橫向捲。** 使用者打進來的東西不受控 —— 一條 Google 地圖長網址、
一整串「〒131-0045 東京都墨田区押上２丁目２０−3」、從別處貼來的一行字 —— 都要斷得掉。

兩件事一起做才有效:

- `overflow-wrap:anywhere` 讓那些字串斷得掉
- **`min-width:0`** 給 grid／flex 的子項。它們預設是 `min-width:auto`,
  也就是「不肯縮到比內容窄」,少了這條,一個長字串就把整列連同整頁撐出去

最後補一道 `body{overflow-x:clip}`。用 `clip` 不用 `hidden` ——
`hidden` 會讓 body 變成捲動容器,頂上那條 sticky 的標題列會跟著壞掉。

## 每人分多少(2026-10-04)

記一筆的對話框:「誰分攤」下面多一排「每人分多少」—— 預設**平分**;選**各自設定**就每個勾了的人一格金額(這筆的幣別)。
**沒填的人平分剩下的**(例:¥9,000、佳瑜填 ¥1,000 → 其他四人各 ¥2,000);一格都不填就是全部平分。
空格子的標籤寫「阿輝 · 平分 ¥2,000」(設計系統的輸入框空著時標籤躺在格子裡,淡字看不到,所以寫在標籤上),下面一句講剩多少給幾個人。
填的加起來比總額多、或每個人都填了卻對不上總額 → 不存,講出兩個數字(伺服器也擋,`why: "split"`)。
花費那一列寫出每個人分多少(「阿輝 ¥2,000、佳瑜 ¥1,000…」),不再寫「每人」;分帳頁的「該付」照這個算。
存在 Notion「花費」表的 **分攤金額** 欄(`代號:金額` 逗號分隔,空的 = 平分)。改帳時沒帶這一欄的舊版 App 不會把它洗掉。
驗收:`probes/custom-split.js`、`api-trip-test.js`(自訂金額那段)。

## AI 讀過的照片(2026-10-04)

**只有花費和交通**(收據、車票 —— Lulu 選的)。AI 讀完一張照片、讀到的是帳或交通,App 就在背景把那張(已經縮成長邊 1600px 的 JPEG)
用 `resource=photo` 傳上去,拿到 Notion 的上傳編號;存那一筆時帶 `photo`,伺服器掛到「花費」「交通」表的 **照片** 欄。
一張收據拆成好幾筆 → 只傳一次,每一筆掛同一張。手動記一筆、AI 只打字沒放照片、自己改一段交通,都不傳也不帶。

- 花費那一列在分類旁邊、交通卡(飛機卡在最下面那一行)有 32×32 的小縮圖;點了放大,點照片放到原寬(長收據往下捲),關閉/點外面/Esc 收起來。
- Notion 給的網址 **1 小時後失效**:縮圖載不出來,有網路就重讀一次資料(一分鐘最多一次),沒網路就先藏起來。
- Notion 的上傳 **1 小時內要掛上去**:存的時候超過 50 分鐘就重傳。掛不上去(過期、Notion 不收)**不擋存檔** ——
  伺服器拿掉照片再存一次、回 `photoLost`,App 在「記下來了」後面加「(照片沒存到)」。
- 能記帳或能動交通的人才能傳(就是能把照片掛上去的人)。
- 驗收:`probes/ai-photo.js`(一般、`?photofail=1`)、`api-trip-test.js` 照片那段;fixture 的 `photo=1` 讓第一筆花費和第一段交通先有照片(截圖用)。

## AI 讀到好幾筆:一批,隨意換筆、最後一起存(2026-10-12)

AI 讀到兩筆以上(好幾筆帳、好幾段交通、好幾個行程或願望、車票這種交通 + 花費的複合)就是**一批**,不再「存一張滑走一張」:
- 卡片上面一排**編號**(radio chip),點了換到那一筆;卡片上**左右滑**也換。複合的編號寫種類(「1 交通」「2 花費」),換筆會換成那一種對話框。
- 改到一半換走,**改的東西留著**(整張表存成草稿,換回來倒回去)。卡片照樣疊著、右上角「第幾 / 共幾」、60% 高。
- **往右滑是下一筆(1 → 2 → 3)、往左滑是上一筆**(Lulu 糾正過一次:一開始做反了)。
- **按著拖,卡片跟著手指走**(同一天 Lulu 補的:「不是滑掉才動,這樣看不出可以滑」):往左拖卡片往左、往右拖往右,帶一點旋轉;
  放手時拖過 70px(或甩得夠快)就從那個位置接著翻,不夠就彈回中間。從打字的格子開始拖不算;上下捲照常(`touch-action: pan-y`)。
- **換筆像翻一疊牌**:最上面那張往手指的方向飛出去(下一筆 → 右、上一筆 → 左),到邊上換到最後面、縮著退下去,後面那張往前推上來;
  點編號也是同一個動畫。**會循環**:最後一筆再往右滑回到第一筆,所以後面一直疊著(總數 - 1,最多畫兩張)。
  飛的是複製出來的那張(值抄過去、`inert`、飛完拿掉),真的那張馬上換成新的那一筆,換筆不用等動畫。
- **「全部存起來(N 筆)」在整疊卡片外面、下面**(同一天 Lulu 補的,卡片裡原本那顆藏起來;卡片裡留「不要這筆」「取消」),
  **左右各一顆圖示鈕**:‹ 往左滑(上一筆)、› 往右滑(下一筆),跟手指拖的方向一樣。設計系統的 Outlined 按鈕只放圖示、方的、跟中間一樣高;
  箭頭是現有的 chevron-down 轉 90 度。
  先每一筆檢查一遍,有問題就跳到第一筆有問題的、**編號標紅**、講缺什麼,一筆都不存;
  都好了才一筆一筆存,存完講「存好了 N 筆」。存到一半失敗:存好的拿掉,停在失敗那一筆。

## 名字

`index.html` 的 `MEMBERS` 每個人有兩個名字:

| 欄位 | 用途 |
| --- | --- |
| `def` | 畫面上顯示的(阿輝、佳瑜、志偉、雅倫、媽) |
| `key` | Notion「付款人／分攤者」select 的選項字串(Chinhui、Chiayu…) |

分開的原因:要改顯示名就只改 `def`,Notion 完全不用動。
如果把兩個混成一個,改名等於要去 Notion 把 select 選項和每一筆既有紀錄重設一遍。

讀回來的時候兩種都認,所以就算哪天真的在 Notion 把選項改成中文,舊紀錄也不會變成「未指定付款人」。
寫出去一律用 `key`,免得 Notion 長出第二組選項。

> Notion 裡的「同行五人」表網站不會讀 —— 那是給人看的,改那裡不會影響網站。

## 加到主畫面(離線也看得到)

**用意只有一個:在東京沒訊號的時候,還看得到行程。** 地鐵裡、郊區、漫遊斷斷續續 ——
那正是最需要看「下一站幾點、在哪」的時候。

### 怎麼裝

| | |
| --- | --- |
| **iPhone** | Safari 打開網址 → 分享 → **加到主畫面** |
| **Android** | Chrome 打開網址 → 右上 `⋮` → **安裝應用程式**(或畫面下方自己冒出來的提示) |

裝完桌面上會多一顆鐵塔圖示,打開沒有網址列。

> **iPhone 一定要裝到主畫面,不能只用 Safari 分頁。**
> Safari 分頁裡存的東西,七天沒打開就可能被系統清掉 —— 出發前先開一次把資料存好、
> 到東京才看,這個做法在分頁裡不成立。加到主畫面的那份不受這條限制。

### 離線的時候看得到什麼

| | |
| --- | --- |
| ✅ 行程、花費、分帳 | **最後一次連上網讀到的那份**。狀態列會寫「離線 · 這是 10/05 14:20 讀到的資料」 |
| ✅ 天氣、地點座標 | 本來就存在瀏覽器裡,跟這次無關 |
| ⚠️ 地圖 | 圖磚是臨時去 OpenStreetMap 抓的,**離線就沒有**。標記和編號還在,底圖是空白的 |
| ⚠️ 字型 | 去 Google Fonts 抓的,離線會換成系統字,版面會跟線上不太一樣 |
| ✅ 記一筆花費 | **沒網路也能記**(2026-09-29 起,有記帳權限的人)。那一筆標「⏳ 還沒送出」,連上網自己送 |
| ❌ 其他編輯 | 行程、交通、許願,以及改和刪既有的花費,離線**都不能做**,按鈕會收起來 |

**為什麼只開放記帳。** 新增一筆花費不會跟別人撞:兩個人各記一筆就是兩筆。
改和刪會撞(你改了時間、他同時刪了),沒網路的時候沒辦法問你要用哪個 —— 那些照舊要連上網。

**記帳離線怎麼運作**
- 記的那一筆存在這台手機(`trippps-outbox:<團>`),**跟副本分開放**:讀到新的一份不會把它蓋掉。
- 連上網就一筆一筆送出。開著的時候斷線(地鐵裡最常見)也一樣:送不出去就先排著,不會像以前那樣被拿掉。
- 還沒送出的那一筆只能「取消這筆」,不能改 —— 改的話會改到一筆 Notion 還沒有的東西。
  伺服器明確拒絕的(例如團主剛好把記帳權限關了)會標「送不出去:原因」,可以再送一次或取消。
- 分帳和統計**照樣算進去**,錢是真的花了。
- 送到一半斷線,手機不知道 Notion 收到了沒有,會再送一次。**「花費」表要有「送出編號」這一欄(文字)**,
  伺服器才認得出同一筆、不會記成兩筆;還沒加這一欄的時候照樣能用,只是那種情況下有機會多一筆。
- 從主畫面 App 打開時就沒網路的話,要**之前連上網時存過副本的新版**才能記帳(舊版副本沒記下你有沒有記帳權限,照舊唯讀)。

(唯一的例外是**從來沒連上過後端**的那種情況,例如 GitHub Pages 上那份。
那時候動的是自己瀏覽器裡的紀錄,跟別人無關,所以照樣能改、能匯出匯入 JSON。)

### 只要連上一次就會自動存

每次成功從 Notion 讀到資料,網站就把那一份存進這台裝置(`tokyo5-snap`),連同時間。
所以**每天有訊號的時候開一次**,離線副本就是當天的。

### 更新會自己來,不會卡在舊版

`sw.js` 走的是「先問網路,問不到才用存的」。有訊號時永遠拿到最新的那一版,
所以改完 push 之後,五個人手機上的網站下次打開就是新的,不用清快取、不用重裝。

> 這一點是刻意選的,而且有代價:線上時不會因為快取而變快。
> 反過來做(先用存的、背景更新)會快一點,但五個人的手機會停在舊版 ——
> 畫面完整、資料也新,只有版面和修好的 bug 是舊的,**而且完全沒有跡象**。
> 寧可不要那個速度。

### 改了圖示要重出 PNG

`icon.svg` 是來源,`icon-192.png` / `icon-512.png` / `icon-maskable-512.png` /
`apple-touch-icon.png` 是產出,跟 `retro-modern.built.css` 一樣**要 commit**

第一次跑的時候 SVG 的註解裡寫了 `--board-bg`(XML 註解不准有連續兩個減號),
整個檔解析失敗,Chrome 畫了四張純底色的方塊,**尺寸完全正確、腳本回報成功**。
