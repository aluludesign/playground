# 那句解釋對所有人顯示,而許願的人可以改自己那一筆

**Lulu 用了剛上線的「兩欄合併」之後提出的兩個改動。第二個是新功能。**

- **改動一**:地圖上方那條 `#map-fix` 的**說明**對所有人顯示。以前只有可編輯的人才畫,
  因為那上面有一顆每按一次都要錢的按鈕 —— **說明跟著動作一起被鎖住了。**
- **改動二**:許願的人可以重新編輯自己那一筆願望,**而「再查一次」移進那個編輯流程**。

---

## 先更正兩件派工時的描述,因為它們改變了範圍

**這一輪有兩個前提是錯的,而兩個都是讀程式碼才發現的。**

### 一、`#map-fix` 不是「只在 `editable()` 才畫」

現況(`7dc467c` 那一輪就做進去的)是:

```js
if (!fixItem || !(editable() || mineWish(fixItem))) { bar.hidden = true; return; }
```

`mineWish()` 早就在裡面了。所以**沒有通行碼的人點自己的願望時,整條是看得到的、
「再查一次」也按得動**。

Lulu 回報的問題仍然是真的,但**範圍比描述窄**。完全沒有解釋的只有兩種:

| | 為什麼 |
| --- | --- |
| 任何人點**行程**那一列 | 行程沒有 `by` 欄位(`stopOut` 沒有、Notion 沒有、舊資料補不回來),所以 `mineWish` 對行程**恆為 false** |
| 點**別人的**願望 | `by` 對不上 |

> **這個更正讓對帳更準。** 如果照著「整條只在 `editable()` 才畫」去寫預期,
> 我會預期唯讀下整條從無到有 —— 而實際上自己的願望那一半本來就有,
> 只有另外兩種是新的。**預期寫錯的話,對上了也是碰巧。**

### 二、「再查一次」的窄路已經存在了

`regeo()` 送出的 URL 會帶 `&wish=<id>`,後端 `wishAsksForItsOwnPlace()` 驗的是
「要查的字串就是那一筆願望的地點欄、那一筆沒有日期、而且住在 itinerary 資料庫裡」。

所以改動二的「把再查一次移進編輯流程」**不是從零長一條路,是把既有的那條路換一個入口**。
後端那一段一個字都不用改。

## 改動一:說明不花錢,動作才花錢

`paintFix()` 的早退那一行以前同時管三件事。拆開之後:

| | 判準 | 理由 |
| --- | --- | --- |
| 整條顯示 | **只看有沒有點過某一列** | 誰在看不影響說明畫不畫 |
| 說明 `#map-fix-t` | **所有人** | 它讀的是 `item.place/title` 和 `pinOf(item)` —— **記憶體裡已經有的東西,零查詢零費用** |
| 「對」`#map-fix-ok` | **所有人** | `confirmPin()` 只改本機 `tokyo5-pin3` 那一筆的 `ok`,**不打任何 API**。而它要退場的虛線圈本來就是每台裝置各自的 —— **作用域一致,就沒有理由分兩種人** |
| 「再查一次」`#map-fix-go` | **`editable()`**(收窄) | 要錢。願望那一半搬進編輯流程了 |

### 「對」那一顆不在 Lulu 的指示裡

它是我提的,協調者批准的。理由:**讓一個看得到虛線圈、卻沒辦法讓它退場的人一直看著它,
那個標記很快就會變成沒有人讀的東西** —— 而那一整條路的價值就是那個標記。

### 「再查一次」收窄是一個**行為的移除**

改之前:沒有通行碼的人在地圖上按得到它(點自己的願望時)。
改之後:按不到,要從「改」進去。

**這正是 Lulu 要的**(「放進『我正在編輯我自己那一筆』的情境裡,它自然被限制在
有意圖的、自己的那一筆上」),但它是移除,所以**登記成一條預期的行為變化,不當成順便**。

而地圖上那顆**留著**,理由是**行程沒有可以搬過去的地方**:行程沒有「誰加的」,
編輯行程本來就要通行碼,拿掉等於把管理員修行程 pin 的唯一入口砍了。

### 合起來,使用者會看到什麼

| 誰 | 點一列之後,地圖上看到 |
| --- | --- |
| 有通行碼 | 說明 + 「對」 + 「再查一次」(跟以前一樣) |
| 沒通行碼、點**自己的願望** | 說明 + 「對」。**「再查一次」不在這裡了**,在「改」裡面 |
| 沒通行碼、點**別人的願望或任何行程** | **說明**(以前是一片空白) |

## 改動二:改我的願望

### 入口

願望列上多一顆「改」,判準是 `mineWish(w)`(= `w.by === myName()`)——
**跟那個 `.mine` 紫框同一個判準,不長第二套**。

`editable()` 沒有出現在這顆按鈕的條件裡是刻意的:它的語意是「我自己那一筆」。
管理員要動別人的願望有既有的路(刪掉、加入行程)。

借 `.wdel` 的樣式,**不新增 class** —— 新 class 要重編,而這裡沒有新的樣式需求。

### 編哪些欄位

| 欄位 | | 理由 |
| --- | --- | --- |
| 標題／去哪(合併後那一欄,含搜尋) | ✅ | 願望的本體 |
| 想說的(`note`) | ✅ | 許願表單裡就有 |
| 哪一天／時間 | ❌ **表上沒有這兩欄** | **願望一有日期就不再是願望了**(後端 `SHAPES.wishes.filter` 是「日期為空」,`wishIn()` 寫著「絕對不寫日期」)。共用 `#edit-form` 等於讓一次誤觸把願望變成行程 —— **這就是為什麼另開一張表,而不是複用那一張** |
| 你是誰(`by`) | ❌ | 改掉它等於把自己那一筆送給別人,**而它是後端唯一擋得住的東西** |
| 票(`votes`) | ❌ | 那是別人的東西 |

### 座標怎麼辦:三種情況一字不差地照抄

`merge-place-field.md` 的「既有的 `place` 不可以被悄悄丟掉」那一節。
**這三種不是可以隨手簡化的分支**,所以程式碼跟 `#edit-form` 那一行完全相同:

```js
place: locatedAt(title) ? title : (title === was.title ? (was.place || "") : "")
```

| | |
| --- | --- |
| 剛挑過 | 用挑的(座標跟著候選一起來,帶 `by:"pick"`) |
| 沒挑、標題沒動 | **原來那個留著** |
| 標題改了又沒挑 | 清空(舊的 `place` 講的是舊的地方,留著會標錯) |

打開編輯時 `seekShowExisting("we-title", w.place)` 把既有的位置講在狀態列上 ——
兩欄合併之後**畫面上沒有地點欄了,那個位置只活在這一行**。
送出後跟行程、跟許願走同一個 `checkPlace()`。

### 「再查一次」放在這裡

在 `we-title` 的狀態列下面,條件跟地圖上那顆同一組:
沒有 `place` 不畫(規則一)、人工表就是答案也不畫。
按下去走既有的 `regeoItem()` → `regeo()` 帶 `&wish=<id>`,**後端那條窄路原封不動能用**。

## 權限怎麼判:一段不假裝驗得了身分的程式

### 前端

`mineWish(w)`。**它是介面層的規則,不是身分驗證** —— `tokyo5-me` 是瀏覽器裡的一個字串。

### 後端 —— 現況會讓這個功能**假裝成功**

`SHAPES.wishes.open = true` 讓沒通行碼的人能 POST / PATCH,**但 PATCH 被夾死了**:

```js
if (shape.open && !keyOK) {
  const now = shape.out(await notion("/pages/" + id));
  body = { title: now.title, place: now.place, note: now.note, by: now.by, votes: body.votes };
}
```

**沒通行碼的人現在只改得動 `votes`。** 所以在放寬之前,那三個人按「存起來」會成功、
畫面會變、**而伺服器悄悄把內容原封不動寫回去** ——
**這個中間狀態比不做還糟,因為它會假裝成功。不要推上線。**

放寬的方式是把夾制的**對象**換掉,而不是把夾制拿掉:

```js
// 沒通行碼:可以改內容,但改不動「這是誰許的」。
body = { title: body.title, place: body.place, note: body.note, by: now.by, votes: body.votes };
```

### 它買到什麼、沒買到什麼

伺服器驗不了身分(跟 geocode 那條窄路撞到的是同一堵牆),所以這裡**不寫一段
假裝驗得了的程式**,改成限制「被問的是什麼」——只是這一次那個限制比 geocode 那條弱。

| | |
| --- | --- |
| ✅ 買到 | 一筆願望的**歸屬**改不掉。`by` 是 `.mine`、「改」按鈕、geocode 窄路三者共同的地基,動不了它,那三個東西就不會被從底下抽掉 |
| ✅ 買到 | 範圍仍然只有 `wishes`(`shape.open`),行程和花費一個字都不鬆 |
| ❌ **沒買到** | **擋不住「A 去改 B 的願望」。** 伺服器看到的兩個請求長得一模一樣 —— **這不是實作偷懶,是伺服器真的分不出來** |
| ❌ 沒買到 | 也擋不住把一筆願望的內容整個換掉 |

> **這一條的邊界是「wishes、而且不改歸屬」,不是「只有本人能改」。**
> **「誰許的誰能改」是介面上的規則,不是鎖。** 下一個人不要在它上面疊東西。
>
> 跟現況比多開了什麼:以前沒通行碼的人能新增任何願望、能改任何一筆的票;
> 現在多了「能改任何一筆的文字」。**在五個朋友的行程站上這是對的取捨,
> 但那是一個取捨,不是一個安全保證。**
>
> 協調者批准這一條時附了一句要帶給 Lulu 的話,就是上面那一句。

### 一個資料形狀的要求,不是防禦性程式碼

送 PATCH 時 **`by` 和 `votes` 一定要一起送回去,即使這裡不讓人改它們**。
後端 `wishIn()` 把「備註」寫成 `joinNote(note, votes)`、把「時間」寫成 `by` ——
**漏送哪一個,那一個在 Notion 上就會被寫成空的**。
漏送 `by` 尤其嚴重:它一空,使用者就再也編不動自己那一筆了。

探針有兩條專門釘這個。

### 05 的差異:登記過的那個風險真的發生了

事前登記寫的是:

> 多一顆會把同一排的東西往右推,**可能把 `+1` 那個名字擠到下一行** ——
> 如果那樣,05 的差異會比「多一顆按鈕」大。**登記在這裡,不要事後歸因。**

實際量到:`y=1856..2289`、409 列、6.39%。位移搜尋:`dy=+51 dx=+0`,而且明講
「是位移**加上**改變」。`crop.py` 切出來一看就清楚:

**`.wm` 那一排(`flex-wrap`)裝不下「改」和「刪掉」,「刪掉」被擠到第二行,
那張卡因此高了 51px,底下整片跟著往下推。**

擠掉的不是 `+1` 那個名字(預測的細節錯了),是「刪掉」——**但形狀是同一個,
而且它被登記過,所以它不是清單外的差異。**

#### 而這裡有一件截圖答不出來的事,它正好是比較重要的那一半

**05 是離線模式截的,`editable()` 為 true —— 那是「管理員看自己的願望」的樣子,
不是那三個人看到的樣子。** 他們沒有「刪掉」,所以那一排可能根本不會換行。

**而 05 是唯一一張願望清單的截圖,它拍不到唯讀。**

所以這件事不是用「看起來應該還好」結案的,是量的。**結論:那三個人那一排不換行。**

| 誰 | `.wm` 的行數(390px) |
| --- | --- |
| 可編輯 + 自己的願望(= 05 拍到的那個) | **2**(`改` 和 `刪掉` 裝不下) |
| 唯讀 + 自己的願望(= 那三個人) | **1** |

#### 而量這件事本身錯了一次,值得記

**第一版比的是兩列的 `offsetHeight`**:自己的 22、別人的 18,不相等 → 紅燈。
看起來像「唯讀也換行了」,實際上那 4px 是**按鈕比純文字高**(`.wdel` 有 padding),
而真的換行會多一整個行高(~18px)。

> **一個閾值式的比較,分不出「高 4px」和「多一行」—— 除非你先知道一行有多高。**

改成直接問那件事本身:`.wm` 的子元素落在**幾個不同的 `offsetTop`** 上。
那是 flex-wrap 有沒有發生的**定義**,不是它的代理指標。

而且補了一條對照組:**先量可編輯那一列,確認它真的是 2** ——
沒有那一條,「唯讀是 1」有可能只是因為這支量錯了東西。

### 看了第 13 張才發現的一件事

「再查一次」拍出來是**整欄寬**的按鈕(`.fld` 是 column flex,子元素預設 `stretch`)。

> **一個每按一次都要錢的動作,畫得比它上面那個輸入框還醒目** ——
> 而把它搬進編輯框的理由正是「不要讓人隨手按」。

加了 `align-self:flex-start`。**程式是對的、探針是綠的,而它長得跟它的意思相反** ——
這就是「沒有截圖的介面等於沒有人看過」買到的東西,跟 `block-05` 那一次同形。

### 那一條在兩個寬度下條數不一樣,而那是刻意的

「可編輯 + 自己的願望 → 那一排換行了」**只在 390 下斷言**。

理由不是「1100 下測不到」,是**沒有獨立證據**:390 有 05 那張截圖量到的
「高了 51px、位移搜尋說 `dy=+51`」可以當期望值的來源;
1100 沒有對應的截圖,在那裡寫一條「不換行」就是**把現況抄成期望值**(工具陷阱 12)。
所以那個寬度只把量到的數字印出來,不下斷言,而且輸出裡寫明為什麼。

# 後續一輪:「改」不可以編輯一份凍結的副本

**同步(把 `origin/main` 併進 `feat/wish-edit`,`18b7525`)之後量到的一個行為衝突,
而兩邊各自都對。**

```js
editable()   = (online ? canEdit : !snapAt)    ← main 改的:看歷史快照時不可編輯
「改」的條件  = mineWish(w)                      ← 這個分支刻意繞過 editable()
```

繞過 `editable()` 是**刻意且正確的** —— 這條路存在的理由正是那三個沒有通行碼的人。
問題在於 **`editable()` 同時承載兩個意思**:

```
「你沒有通行碼」      ← 「改」應該無視它
「你在看一份副本」    ← 「改」應該尊重它
```

繞過一個的時候,連另一個一起繞過了。

## 症狀:一個我們自己造的無聲失敗

`SNAP=1` 的 fixture、390 寬,修之前實測:

| | |
| --- | --- |
| 橫幅 | `離線 · 這是 09/19 09:30 讀到的資料 · 不能編輯` |
| `add-stop-btn.hidden` | `true`(`editable()=false`,一致) |
| 「刪掉」 | 0 顆(一致) |
| **「改」** | **1 顆,而且點下去編輯框真的開** ← 跟橫幅矛盾 |

而**存下去是無聲失敗**:`updateWish()` 會 `Object.assign` 並 `renderWishes()`
(畫面看起來成功了),但 `saveLocal()` 開頭是 `if (online || snapAt) return;` ——
什麼都沒存,重新整理就沒了,**而且沒有任何地方會說一句**。

量到的:在拆掉上面那層擋板的實驗樹上,送出之後清單那一列的標題
從 `橫濱 港灣未來` 變成 `我在副本上亂改的標題`。**看起來完全像成功了。**

> 那正是這一輪自己的紀錄裡定為禁止的東西:
> 「**新的、我們自己造的無聲失敗,比功能不完整糟**」(見「上線的綁定條件」)。
> 它當時講的是後端沒放寬就先推前端,而這一次同一個形狀長在快照模式上。

## 決定與寫法

**「改」要同時滿足「是我許的」和「不是在看快照」。**
兩邊的設計意圖都保住:沒有通行碼的人照樣能改自己的願望,而沒有人能編輯一份凍結的副本。

`editable()` 的定義**一個字都沒動** —— 它現在的定義是對的,而且加行程、刪掉、
地圖上那顆「再查一次」都還靠著它同時管兩件事。改的是**把那兩個意思拆出名字**:

```js
const onSnapshot   = () => !online && !!snapAt;        // 就是 editable() 離線那一邊的 !snapAt
const mayEditWish  = w  => mineWish(w) && !onSnapshot();
function mayWriteWish() {                               // 形狀跟既有的 mayEdit() 一樣
  if (!onSnapshot()) return true;
  flash("這是離線副本,改了存不下來 —— 連上網之後會換成最新的");
  return false;
}
```

`mineWish()` 本身留著不動:`.mine` 那個紫框問的是「這是誰許的」,
**那是一個事實,跟現在能不能寫沒有關係**。

四個掛點,兩側都擋:

| 層 | 改成 |
| --- | --- |
| 繪製(`renderWishes`) | `mineWish(w)` → `mayEditWish(w)`,按鈕不畫 |
| 開表單(`openWishEdit`) | `mineWish(w)` → `mayEditWish(w)`,手動戳 DOM 也開不了 |
| 送出(`wish-edit-form` 的 submit) | `if (!mayWriteWish()) { closeWishEdit(); return; }` |
| 寫入(`updateWish`) | `if (!mayWriteWish()) return;` |

送出那一層**不能只靠 `updateWish()` 裡那一行**:這個 handler 在 `updateWish()`
之後還會跑 `checkPlace()`(那會去查地名),而在一份凍結的副本上,
那整件事從第一步就不該發生。

### `#wish-edit-overlay` 開著的時候切進快照模式

`renderEditAbility()` 末尾加了 `if (onSnapshot()) closeWishEdit();`,
**而它掛在 `onSnapshot()` 上,不是掛在上面那個 `if (!on)` 裡** ——
線上唯讀(有連線、沒通行碼)時那張表**該**留著,那正是這條路存在的理由。

**這條路現在走不到,而那是查過的、不是假設的:** 唯一把 `snapAt` 設起來的是
`goLocal()`,而 `goLocal()` 只在開機那一趟 `goOnline()` 失敗時跑 ——
那時候不可能有表開著。站上沒有任何「執行中切回離線」的入口(登出是 `location.reload()`)。

留著那一行的理由是它便宜,而且「唯讀時把會改資料的入口收起來」本來就是那個函式的工作。
下一個人加一條「連線斷了就 `goLocal()`」的路時,不會順手造出
「表開著、按存起來、無聲失敗」那個組合。

## 探針

新斷言掛在 `probes/pwa.js` 的 `SNAP=1` 那一段(那是唯一會進入快照模式的探針)。

| 條 | 是什麼 |
| --- | --- |
| `自己那筆願望在畫面上 >= 1` | **對照組**。沒有它,下面兩條在「畫面上根本沒有自己的願望」時會是空著綠的 |
| `願望的_改_幾顆 === 0` | 主斷言:快照下那顆按鈕不該畫 |
| `戳一顆 data-edit-wish 進去再點 → 編輯框仍然 hidden` | 第二層:`openWishEdit()` 那層也要擋 |
| (沒有副本時)`改` 還在、而且戳得開 | **反過來的那一半**,見下 |

`願望的_刪掉_幾顆` 只印數字、不下斷言:它的判準是 `editable()`,改動前後都是 0,
**斷言它證明不了這一輪的任何事**(工具陷阱 12 的形狀)。

## 新踩到的陷阱

### zsh 會把 `git show $c:path` 裡的 `:a` 當成歷史修飾符吃掉

```sh
for c in be3e0ef 97deeca; do git show $c:adopt-harness/... ; done
#                                      ^^ 這裡
# → fatal: ambiguous argument '/…/playground/97deecadopt-harness/...'
```

`:a`(絕對路徑)、`:t`(檔名)…… 都是 zsh 的修飾符,**雙引號也擋不住**。
`adopt-harness` 的 `a` 被吃掉,剩下 `dopt-harness`,而錯誤訊息長得像「這個 commit 不存在」。
寫成 `"${c}":adopt-harness/...` 就好。

> **跟這一輪被交代要小心的那個坑同一個家族**(`git worktree add` 因為分詞
> 停在當前 HEAD,而 `git worktree list` 看起來完全正常):
> **shell 安靜地改寫了你給 git 的參數,而 git 的錯誤訊息講的是改寫之後那個東西。**
> 判準:任何 `$var` 後面直接接 `:` 的地方,都加上大括號。

### 負向對照樹:`cmp` 過了

`git worktree add --detach /tmp/wt-snapfix 18b7525` 之後:

```
$ cmp <主樹>/tokyo-trip/index.html /tmp/wt-snapfix/tokyo-trip/index.html
… differ: char 76441, line 1095        ← ✓ 兩棵樹真的不同
$ grep -c 'onSnapshot\|mayEditWish' /tmp/wt-snapfix/tokyo-trip/index.html
0                                       ← ✓ 對照樹上沒有這一輪的東西
```

**而這一次那個坑本來就看不見:** 這一輪的改動是**未提交**的,
所以就算 worktree 真的停在當前 HEAD,它拿到的也還是修之前那份 —— 對照照樣成立。
**也就是說 `cmp` 這一步在這一輪不會失敗,它保護的是下一輪。**
(上一隻踩到的那次,對照要指的是一個**別的** commit,那時它才咬得到人。)

### `probes/drawer.js` 在 390 寬有 2 條紅,而那是它的量測範圍外

`底下的版面至少留得到 240px` 和 `往最寬拖 → 停在第 4 檔` 兩條,
