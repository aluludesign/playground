# 地名查詢的退路:使用者主動觸發的「再查一次」

**這不是一塊 design-system 轉換**,所以檔名不叫 `block-NN-*`。
它改的是 `tokyo-trip/index.html` 和 `tokyo-trip/api/notion.js` 的行為,
**不碰 `design-system/`、不碰樣式層的轉換進度**。
但驗收工具和紀律跟轉換共用 —— `shoot.sh`、十一張截圖、事前登記與對帳。

驗收規則走的是**「不該改變外觀」那一套**:十一張要**逐位元組相同**,
任何非零一律當成問題查。新長出來的東西全部躲在
「使用者點過某一列之後」這個互動狀態裡,而那個狀態十一張都沒有截到。

---

## 為什麼要做

Nominatim **不確定的時候不會說**。同一份格式、同樣的欄位:

```
淺草寺  → 35.7134,139.7955  淺草寺, 浅草二丁目, 臺東區, 東京都      對
泡溫泉  → 24.6985,99.6963   温泉镇, 保山市, 云南省, 中国            錯,差三千公里
```

沒有信心值、沒有警告。`pinFor()` 拿到座標就畫 pin,它**無從判斷第二筆是錯的**。
使用者看到的是一顆很有自信的錯 pin —— 而「很有自信的錯答案」正是這個專案
一路在拆的那種失敗:**安靜地量到了別的東西。**

程式偵測不到它,但**使用者知道**:打「泡溫泉」的人知道那不是地名,
看到 pin 跑到雲南的人也知道不對。**所以偵測器是人,不是程式。**

實測資料(11 個地名,兩家並排)在 scratchpad 的 `geotest-result.txt`。
關鍵差別:退路那家每筆都帶精度(`ROOFTOP` / `GEOMETRIC_CENTER` / `APPROXIMATE`),
而且非地名會明確回「查無」,不會硬給一個。

**不換掉 Nominatim。** 它免費、不用金鑰、對繁體地名夠好,而且 90% 的情況是對的。
加的是一條**使用者按下去才會走**的退路 —— 所以退路那家的費用只在有人說「不對」時發生。

## 三個要自己決定的,以及理由

### 決定 1:再查一次成功之後,快取蓋掉舊的,同一個 key、同一份 `tokyo5-pin3`

**做法**:按下去的當下,先把這一筆的候選字串(`place` 和 `title`)在 `pins` 裡
**全部設成 `null`**,再把查到的那一個寫回去。整份照舊存進 `tokyo5-pin3`。

**為什麼不開第二份快取**:`pinOf()` / `pinFor()` / `stopWx()` 都讀 `pins`。
多一份「修正過的座標」就等於**同一個問題有兩個答案來源** ——
那正是這個 repo 反覆抓到的那個形狀(fixture 的 key 差一個字元、
token 到底是誰說了算)。一個 key 一個答案,查得到就是它。

**為什麼要先全部設成 `null`**:不先清,會出現「地點欄的舊錯座標還在,
標題欄查到了新的對座標」,而 `pinOf` 先看地點欄 —— **使用者按了修正,畫面沒變**。
清成 `null`(不是 `delete`)是因為 `null` 在這份快取裡本來就有意思:
「查過了,沒有」。`delete` 會讓下一次重畫又跑去問 Nominatim。

**為什麼不改 key**:`57473b5` 那次改 `tokyo5-pin2` 是因為**一整批**座標依規則錯掉,
而且長得跟對的一模一樣。這次不一樣:修正是**一次一筆、由使用者發起**的,
沒有「大家瀏覽器裡有一批壞資料」這回事。改 key 會把每個人所有查好的座標一起丟掉。

**代價**:修正只存在按下去的那台裝置上。五個人各修各的。
要讓修正跟著行程走,座標得存回 Notion —— 那是另一個決定,這一塊沒做。

### 決定 2:回「概略」時照樣標,但**標成看得出來是概略的**

`APPROXIMATE` 的意思是「這是行政區的概略中心」。實測裡「東京都廳」就是這樣 ——
回的是「日本東京都」,一顆落在東京都幾何中心的 pin。**它看起來跟精確的 pin 一模一樣。**

**做法**:照樣標,但

1. 快取那一筆多帶 `ap:1`;
2. 那顆 pin 畫成**虛線圈**,標籤前面加「約 」;
3. flash 說清楚:只查到大概的範圍、標的是那一區的中心、地名打完整會更準。

**為什麼不直接丟掉**:丟掉等於回到「查無」,而「大概在東京都」比「不知道在哪」
對排行程是有用的 —— 使用者要的是相對位置。

**為什麼不只講一句 flash 就算**:flash 2.8 秒就沒了,而那顆 pin 會留在地圖上好幾天。
**把信心值只用在一則會消失的訊息上,等於沒用。** 這一塊最有價值的東西就是
「終於有信心值了」,所以它要留在**那顆 pin 自己身上**。

**代價**:多兩條 CSS 和一個「約 」前綴,而且**這一輪沒有任何截圖看得到它**(N3)。

### 決定 3:回「查無」時就說還是找不到,並且不留下任何座標

文案:「『泡溫泉』還是找不到 —— 它可能不是一個地名,地圖上不會顯示」。

**為什麼要講「可能不是一個地名」**:README 早就寫了「像『泡溫泉』這種本來就不是地名的,
標不出來是正確的」。使用者按「再查一次」的心智是「它應該查得到」,
所以回饋要順手把那個預期修掉,不然他會一直按。

**附帶的一件事**:退路那家對非地名會明確回查無,這本身就是資訊 ——
兩家都說沒有,那多半真的沒有。

### 順帶決定:退路要通行碼,按鈕只給編輯者看

退路那家**每一筆都要錢**,而且付錢的是 Lulu 的信用卡。
公開的 GET 端點等於把額度開給全世界。所以這個分支跟寫入走同一條規則
(`TRIP_KEY`),前端也只在 `editable()` 為真時才畫那顆按鈕 ——
不畫一顆按下去一定 401 的按鈕。

**代價**:唯讀的人看到錯 pin 也修不了。這跟「唯讀的人也改不了行程文字」一致,
但它是個真的取捨:**要改掉的話,server 端一個判斷、前端一個判斷,各一行。**

## 實際結果

### 介面長什麼樣

在時間軸或許願清單上**點某一列**(那個動作本來就會打開地圖並移到那個點),
地圖上方、兩顆圖層開關下面多出一條:

```
「淺草寺」不在這裡?                    [ 再查一次 ]
「泡溫泉」沒標上去                      [ 再查一次 ]
```

**只在點過某一列之後出現**,而且唯讀的人不畫(退路要通行碼)。
從 DAY 或許願那顆地圖按鈕進來、切換日期、收起地圖 —— 三種情況都收回去。
**這就是十一張截圖零改變的機制**,不是把它做小做淡,是它在那些狀態裡根本不存在。

按下去之後的四種回答,全部走現有的 `flash()`(站上第 32 次用它):

| 情況 | 狀態列 |
| --- | --- |
| 查到精確位置 | 「『X』重新標好了」 |
| 查出來跟原本同一個位置 | 「『X』再查一次還是同一個位置」 |
| 只查到大概的範圍 | 「『X』只查到大概的範圍,標的是那一區的中心 —— 地名打完整會更準」 |
| 還是找不到 | 「『X』還是找不到 —— 它可能不是一個地名,地圖上不會顯示」 |
| 退路本身壞掉／沒設金鑰 | 「再查一次沒成功:<原因>」,**而且舊座標原封不動** |

加上「只查到大概的範圍」那顆 pin 會畫成**虛線圈**、標籤前面加「約 」。
**文案裡沒有任何服務商的名字**(探針有一條專門在看這件事)。

### 兩張圖在跳,而兩張都不是這次改的

改完之後連跑五次 `shoot.sh`,02–10 **五次逐位元組相同**。01 和 11 各跳過:

| | 01 | 11 |
| --- | --- | --- |
| 五次裡不同的 | 1 次 | 3 次 |
| 形狀 | 2.1481% / `y=454..651` / **1 群** / **水平位移 dx=27** | 8 px / 1881600 (0.0004%) / 6 群,每群 1 列 / **全部落在 x=86 那一行** |
| 是什麼 | **`ADOPTION.md` 已登記的 01 雙穩態**,四個特徵全中,重截一次就回到相同 | **新的**,登記在下面 |

> **01 那一次值得記一件事:`pngdiff.py --shift` 幫不上忙。**
> 它搜的是**垂直**位移,而 01 這個雙穩態是 `scrollLeft` 差 27px,是**水平**的 ——
> 跑出來的結論是「沒有任何位移對得上,這一帶是真的被改掉了」。
> 那句話在這個情境下**是錯的**,而且它講得很有自信。
> (`ADOPTION.md`「工具還缺什麼」第 2 條就寫著「仍然沒做的:全圖比對時不會自動報 x 方向的群」——
> 只是沒有人把它跟 `--shift` 只有垂直版這件事連起來。)
> 水平位移是另外寫了十幾行搜出來的:`dx=27,殘差 2.81%`。**那十幾行值得進 `pngdiff.py`**,
> 這一輪沒做 —— 而這句話本身在這個 repo 裡有前科(見 ADOPTION「累犯」那一段)。
