# 拆掉 `#map-fix`：拆之前的資料盤點

**Lulu 看到的**：「『晴空塔』不在這裡?　→　已經不會有這種說明小字了吧　怎麼還出現」

## 它為什麼還在

上一輪（`search-escalate`）退場的是**編輯框裡**那顆 `#we-again`。
地圖上方這一條 `#map-fix` 是另一個東西，刻意留下來的，筆記裡還註明
「`regeoItem()` 沒有動 —— 地圖那顆『再查一次』還在用它」。

**沒有任何一輪決定要拆它。** 這一輪才是。

## 為什麼四輪下來沒有人發現它不對

`geocode-retry`、`geocode-place-and-confirm`、`geocode-outside-and-notice`、
`geocode-via-in-cache` 四份文件裡各寫了一次同一句話：

> 「`#map-fix` 那幾種狀態**一樣沒有截圖**……文字、按鈕的顯示／隱藏都量了，
> **外觀沒有人看過**。」

它躲在互動狀態裡（要先點過清單上某一列才出現），
而**躲起來正是每一輪「其餘九張逐位元組相同」的機制本身**。
兩件事在那幾輪裡是互相排斥的，每一輪都選了後者。

> **「量過」和「看過」是兩件事，而這個 repo 的工具只擅長前者。**
> 一個元件可以連續四輪通過所有斷言，同時沒有任何一個人真的看過它。

## 前提消失了，跟上一輪同一個形狀

「不在這裡?」的前提是「**程式自己猜了一個位置，可能猜錯**」。

`merge-place-field` 之後程式不再自己猜 —— 座標是人從候選清單裡親手挑的，
存下來會標 `by:"pick"`。**對一個親手挑的點問「不在這裡?」，問的是一個
已經被回答過的問題。**

而現在的程式不分親手挑的和舊資料：只要有 pin、不是人工表、沒在問「對嗎」，
一律問「不在這裡?」。

## 拆掉不會讓舊座標沒救

四張表單都有搜尋鈕（新增行程 `sf-title`、新增願望 `wf-title`、
編輯行程 `se-title`、編輯願望 `we-title`），而從候選清單挑一筆會寫：

```js
pins[name] = { la: +r.lat, lo: +r.lon, by: "pick", at: hitAddr(r) };
```

**「改 → 搜尋 → 重新挑一次」跟那顆「再查一次」做的是同一件事，而且結果更好**
（標記成親手挑的，下次開場對帳會跳過它）。

## 拆了(2026-09-22)

Lulu 的授權是在她認出這是什麼東西之後給的,原話:**「把那條小字和那兩顆鈕拿掉」**。

在那之前她問過一句「這題是在改什麼啊」—— **她不認得的是代號,不是那個東西**。
整件事的起點就是她自己回報的那句「『晴空塔』不在這裡?」。
**沒有人用她看得懂的說法跟她講過「拆 `#map-fix`」是什麼意思**,那是我們的問題。
登記下來:**要她裁決一個東西的去留,先用她看得到的樣子描述它,不要用它的 id。**

拿掉的:`#map-fix` 那一條、`#map-fix-ok`、`#map-fix-go`、`.mapfix` / `.mf-t` 兩條 CSS、
`paintFix()` 和它六種文案、`regeoItem()`、`regeo()`、`confirmPin()`,
以及散在換天／點行程列／點願望列／開關地圖四條路徑上的五個 `paintFix()` 呼叫端。

`index.html` −212 / +28(加的全是墓碑註解)。

### 盤點時算錯了一個,查了才知道

前一版寫「`confirmPin()` 還有另一個呼叫端活著,**留**」。**那一行是註解,不是呼叫。**
逐行分類之後,`confirmPin()` 真正的呼叫端只有 `#map-fix-ok` 的 handler 一個 ——
按鈕拆掉它就是孤兒,跟著走。

`outsidePin()`(三個真呼叫)和 `savePins()`(六個)確實要留,那兩個判斷是對的。

> **數呼叫端的時候,判準要能分辨「定義／呼叫／註解裡提到」。**
> 這個 repo 的註解密度特別高,`grep -c` 數出來的東西會把註解算進去。

### 因此少掉的東西,誠實登記

`at.ap = 1`(「這顆 pin 只查到大概範圍」)**全檔只有 `regeoItem()` 會設**。
它退場之後**新的概略 pin 再也產生不出來**,於是:

- 舊快取(`tokyo5-pin3`)裡已經有 `ap:1` 而沒按過「對」的那些,會繼續畫成
  虛線圈 + 標籤前面「約 」,而讓那個記號退場的「對」不在了。
- **但那不是死路**:改地點欄 → 搜尋 → 重新挑一次,會用 `by:"pick"` 蓋掉整筆,
  記號跟著消失。退場的是按鈕,不是那條路。
- `.pin.approx` 的畫法和 CSS 都留著 —— 那是誠實:那顆 pin 真的只是概略的。

**沒有任何探針在守的三件事**(入口沒了,走不到):概略 pin 那一整套行為、
「再查一次」失敗時不弄丟舊座標、願望那條路送 `wish=` 的 URL 形狀。

### 探針動了手術

`probes/geofix.js` 916 → 673 行,**退掉 243 行**:3–7 段、11 / 11b 的說明斷言、
14b / 14c / 14d。每一處留墓碑寫清楚原本量什麼、為什麼沒有對象了。

其中一條**照抄舊斷言會得到假紅燈**:舊版斷言「`pins["NRT 成田 T1"]` 在快取裡而且帶 via」,
量過才知道成田那顆 pin **從來沒進過快取** —— `pinOf` 第二步直接問 `outsidePin()`,
現算現回,不寫快取。舊版之所以是綠的,是因為前面幾段的 `regeoItem()` 會把表的值
寫回去。那條路退場,這條斷言量的東西就不存在了。
改成問看得見的那件事:**地圖上有沒有那顆 pin,以及接住它有沒有花錢**。

跑完:**geofix 76、escalate 25、seek 53、drawer 10,全過。**
