# 拆掉 `#map-fix`：拆之前的資料盤點

**Lulu 看到的**：「『晴空塔』不在這裡?　→　已經不會有這種說明小字了吧　怎麼還出現」

## 它為什麼還在

上一輪（`search-escalate`）退場的是**編輯框裡**那顆 `#we-again`。
地圖上方這一條 `#map-fix` 是另一個東西，刻意留下來的，筆記裡還註明
「`regeoItem()` 沒有動 —— 地圖那顆『再查一次』還在用它」。

**沒有任何一輪決定要拆它。** 這一輪才是。

## 為什麼四輪下來沒有人發現它不對

`geocode-retry`、`geocode-place-and-confirm`、`geocode-outside-and-notice`、
`geocode-via-in-cache` 四份文件裡各寫了一次同一句話：

> 「`#map-fix` 那幾種狀態**一樣沒有截圖**……文字、按鈕的顯示／隱藏都量了，
> **外觀沒有人看過**。」

它躲在互動狀態裡（要先點過清單上某一列才出現），
而**躲起來正是每一輪「其餘九張逐位元組相同」的機制本身**。
兩件事在那幾輪裡是互相排斥的，每一輪都選了後者。

> **「量過」和「看過」是兩件事，而這個 repo 的工具只擅長前者。**
> 一個元件可以連續四輪通過所有斷言，同時沒有任何一個人真的看過它。

## 前提消失了，跟上一輪同一個形狀

「不在這裡?」的前提是「**程式自己猜了一個位置，可能猜錯**」。

`merge-place-field` 之後程式不再自己猜 —— 座標是人從候選清單裡親手挑的，
存下來會標 `by:"pick"`。**對一個親手挑的點問「不在這裡?」，問的是一個
已經被回答過的問題。**

而現在的程式不分親手挑的和舊資料：只要有 pin、不是人工表、沒在問「對嗎」，
一律問「不在這裡?」。

## 拆掉不會讓舊座標沒救

四張表單都有搜尋鈕（新增行程 `sf-title`、新增願望 `wf-title`、
編輯行程 `se-title`、編輯願望 `we-title`），而從候選清單挑一筆會寫：

```js
pins[name] = { la: +r.lat, lo: +r.lon, by: "pick", at: hitAddr(r) };
```

**「改 → 搜尋 → 重新挑一次」跟那顆「再查一次」做的是同一件事，而且結果更好**
（標記成親手挑的，下次開場對帳會跳過它）。
