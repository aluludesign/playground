## 做了什麼

### 1. `shoot.sh`:多兩張截圖

```sh
shot 10-exp-form         390 1700 "d.getElementById('tab-cost').click(); d.getElementById('add-exp-btn').click();" \
                                  "#exp-form:not([hidden]) .rm-input:7+,#exp-form .who label:4+"
shot 11-exp-edit-dialog  390 1100 "d.getElementById('tab-cost').click(); d.querySelector('[data-edit-exp]').click();" \
                                  "#exp-edit-overlay:not([hidden]) .rm-input:7+,#exp-edit-overlay .who label:4+"
```

`ADOPTION.md` 建議的那一行是 `shot 10-exp-form 390 1400 ... ".who label:4+"`。
三處跟建議不一樣,每一處都有理由:

- **高度 1400 → 1700。** 1400(我先試的是 1500)切掉了「備註」欄位和底下的
  取消／記下來兩顆按鈕。**16 個欄位裡的第 8 個看不到,這一塊就白做了。**
  1700 剛好連表單下面第一張花費卡都帶到。
- **兩張不是一張。** 建議只提 `#exp-form`。`#exp-edit-overlay` 另外有 8 個欄位、
  5 個膠囊、5 個核取方塊,而且 app 開它的時候會自己 `focus()` 到 `xe-title` ——
  那是第二個有對焦狀態的畫面(08 是第一個)。不截它等於只還一半的債。
- **斷言挑 `.who label` 而不是 `input`。** `ef-who` / `xe-who` 在 markup 裡是
  **空的 `<div>`**,五個膠囊是 JS 跑起來才產生的(`index.html:2447` / `:2496`)。
  這正好符合「斷言要挑只有 app 真的跑起來才會存在的東西」——
  08 / 09 當初被收緊就是因為它們量的是靜態 markup。

### 2. `shoot.sh` / `probe.sh`:`SRC=` 開關

這一塊的核心是「拿新截圖回頭比對兩輪之前」,而兩輪之前的樣子只存在於舊 commit 裡。
`ADOPTION.md`「工具的陷阱 1」給的做法是 `git stash` 或 checkout ——
**那等於動共用工作樹裡的 `tokyo-trip/index.html`**,而這一輪被明確要求不准碰它
(另一條工作線可能在動它)。

所以做進工具裡:

```sh
git worktree add /tmp/wt-8b4ee7c 8b4ee7c
ln -s <repo>/design-system/node_modules /tmp/wt-8b4ee7c/design-system/node_modules
SRC=/tmp/wt-8b4ee7c/tokyo-trip ./shoot.sh expform-pre-label
SRC=/tmp/wt-8b4ee7c/tokyo-trip WIDTH=390 ./probe.sh probes/who.js
```

配套的兩件事:

- build 的輸入輸出跟著 `$SRC` 走。寫死 `../tokyo-trip` 的話會變成
  **「編主樹、截別的樹」**,而兩邊對不上不會有任何錯誤訊息。
- 出處紀錄多印一行 `來源`,而且**不是預設來源時大聲說**下面那幾行
  HEAD／工作樹統計是**主樹**的、跟這批圖無關,另外印來源樹自己的 HEAD。
  (沒有這一段的話,出處看起來完全正常而內容全錯 —— 這個專案的招牌形狀。)

### 5. `pngdiff.py`:`--band` / `--x` / `--shift` 垂直位移搜尋

```
./pngdiff.py a.png b.png --band <y0> <y1> [--x <x0> <x1>] [--shift <N>]
```

回答的是那個真正要問的問題:**這一帶的內容變了,還是只是被推走了?**

`ADOPTION.md`「工具還缺什麼」第 2 條登記了「pngdiff 要給區域」,
而 `block-04` 為了診斷 01 的雙穩態**手寫過一支水平版的位移搜尋、用完就丟** ——
那一份自己的紀錄就寫著「那正是第 1 條那個累犯的形狀,它值得進 `pngdiff.py`」。
這一輪需要它(`.who` 在三個 commit 的截圖裡位於不同的 y),所以收進去,
並且改成**垂直**的 —— 垂直才是常態,每一塊轉換都會把下面的東西整片往下推。

預設行為一個字都沒變,驗過。

### 6. `crop.py`:多一個 `dy`

`./crop.py a.png b.png y0 y1 out.png [dy]`,把右邊那張往下位移 dy 再切。
沒有它的話,「同一個 y 切兩張」切到的常常根本不是同一個元件 ——
看起來像整個變了,其實只是錯位。先用 `pngdiff --shift` 問出 dy,再帶進來,
眼睛看到的才是同一個東西的前後。

### 7. `probes/who.js`

`.who` 的逐項盤點:膠囊的 `color` / `letterSpacing`(第三塊凍的)、
核取方塊的 `width` / `background` / `fontSize` / `lineHeight`(第四塊凍的),
外加**兩輪都沒有人登記過的幾項**(`fontWeight` / `marginBottom` / `display` /
`padding` / `border` / `radius` / `gap`)和**小數點後三位的幾何**。

小數點是關鍵:`offsetHeight` 是整數,`65` 在兩邊都一樣看不出東西;
`getBoundingClientRect()` 的 `64.781` 才分得出「真的沒變」和「差了半個像素」。

#### 那兩項「沒有人登記過」的呢

第三塊只登記了 `color` 和 `letter-spacing`,但 `.fld label` 是後代選擇器,
`.who label` 其實把它**整條**都繼承走了。所以我特地量了沒人提過的幾項:

- `font-weight`:`.fld label` 舊值 `400` → `rm-label` 是 `700`。
  **`.who label` 前後都是 `400`** —— 因為 `.who label` 自己沒設,而 `.fld label`
  那條被刪掉之後它就落回預設的 `400`,**跟舊值剛好一樣**。
- `margin-bottom`:`.fld label` 舊值 `0px` → `rm-label` 是 `6px`。
  **`.who label` 前後都是 `0px`**,同樣是落回預設。

**也就是說第三塊沒有漏,但那是運氣不是設計** —— 舊的 `.fld label` 在這兩項上
剛好就是瀏覽器預設值。要是它當初寫的是 `font-weight:600`,
第三塊會在無人登記的情況下把十顆膠囊的字重改掉,而九張截圖一樣看不到。

### 像素上的比對(以及一個差點被誤讀的殘差)

`pngdiff.py --band ... --shift`,限定在 `.who` 那一帶:

| 比對 | 位移 | 結果 |
| --- | --- | --- |
| 10:`957d829` → 現在(只經過第四塊) | `dy=-24`(= 整整 12 CSS px) | **膠囊第二列逐位元組相同**;整組 266 列裡只有 **2 列 / 36 px** 不同 |
| 11:`8b4ee7c` → 現在,第一列膠囊 | `dy=+33` | 單顆膠囊 x 窗格內 **逐位元組相同** |
| 11:`8b4ee7c` → 現在,第二列膠囊 | `dy=+33 / +34` | 找不到任何位移完全命中,殘差約 2–3% |

**第二列那個「找不到完全命中」一開始看起來像「膠囊真的變了」。它不是。**

`.who` 容器高 `135.563`、膠囊高 `64.781` —— **都是小數**,所以第一列和第二列
在裝置像素上本來就落在**不同的次像素相位**。第三塊把整組往下推了 `39.344` CSS px
(= `78.688` 裝置像素,**不是整數**),相位跟著換,邊緣的反鋸齒就不一樣 ——
而任何整數位移都對不回去。

對照組把這件事釘死了:第四塊推的是**整整 12 CSS px = 24 裝置像素**,
於是同一段就出現**逐位元組相同**。**整數位移完全命中、小數位移留下反鋸齒殘差**,
兩邊都量到了。

> **那 36 px 我沒有全部解釋掉。** 它落在 2 個單獨的列(y=2550 / 2575)、
> 6 px × 3 個核取方塊,剛好是原生核取方塊方框的上下緣。
> 同一個 dy 下第二列的核取方塊是逐位元組相同的,所以它不是規則層面的差異;
> 我判斷是原生控制項字形的光柵化,但**沒有量到能證明它的東西**。
> 照實寫在這裡,不要在下一輪被當成新出現的回歸。

## 新踩到的陷阱

### 1. 重編失敗會被 `| sed` 吞掉,腳本照樣往下跑、照樣回報成功

```sh
( cd "$H/../design-system" && ./build.sh ... ) | sed 's/^/  build: /'
```

**`set -e` 之下,管線的結果是最後一個指令(`sed`)的結果,永遠是 0。**
所以 `build.sh` 失敗時 `shoot.sh` 會拿**上一次留在樹裡的舊 `retro-modern.built.css`**
去截圖,一個字都不會多說。

我是這樣撞到的:`SRC=` 指到 `git worktree`,那棵樹的 `design-system/` 沒有
`node_modules`,tailwind 解不到 `tailwindcss/theme.css` ——
**兩批歷史截圖全部是用舊產出截的,而腳本說成功、回傳 0。**

> 錯誤訊息**確實印出來了**。它沒有被讀到,是因為混在 build 的正常輸出裡,
> 而那一段一路被 `| grep`、`| tail` 接走 ——
> **又一次「訊號活著,只是沒有人站在它的頻道上」。**
> 這份文件裡至少已經有四個同形的故事了。

**已修**:build 改成 `if ... > .build.log 2>&1; then ... else 印出來 + exit 3; fi`,
兩支都改。失敗訊息順便告訴你 worktree 要怎麼接 `node_modules`。
驗過:沒接 `node_modules` 時擋下來並印出解法;接上之後正常。

> **這一次結論沒被弄壞是運氣。** `8b4ee7c` / `957d829` 的 `built.css`
> 跟 HEAD 的**內容剛好一樣**(`8b4ee7c` 只差 `/*src:...*/` 那行註解裡的路徑,
> 指紋雜湊 `j5j2pg` 三者相同)。接上 `node_modules` 真正重編之後再截一次,
> **兩組跟先前那兩組逐位元組相同** —— 驗過才敢說運氣好。

### 2. 正向斷言掛掉時,`shoot.sh` 回傳 **0**

`block-04` 修掉了「每一次成功都回傳 1」,**但沒有人檢查反過來的那一半**:
在那之後,不管幾張印 `✗`,它都還是回傳 0,只印一行警告。

也就是說 `./shoot.sh a && <比對>` 會在一批「有畫面是空的」的截圖上**照樣往下跑** ——
而差異式檢查對兩邊都空全綠。**那正是「最貴的一個教訓」那一節在防的東西,
而它的出口一直是開著的。**

**已修**:`FAILED` 時 `exit 4`,警告改走 stderr。
兩個方向都驗過:健康的一批 `exit=0`(11 張全 `✓`),
歷史那一批 `exit=4`(10 / 11 印 `✗`)。

> 這跟 `block-04` 的 trap 是同一種:**修了踩到的那一半,沒有回頭問另一半。**
> 「成功要回傳 0」和「失敗要回傳非零」是兩個斷言,驗一個不等於驗另一個。

### 3. 位移搜尋找不到完全命中,**不一定**代表內容變了

見上面「像素上的比對」。元件的高度是小數(`64.781`)時,被推到一個小數距離
(`39.344` CSS px)就會換一個次像素相位,邊緣的反鋸齒跟著變,
**任何整數位移都對不回去**,而殘差長得像「有東西被改了」。

**判準**:殘差如果集中在**邊緣**、比例是零點幾到幾 %,而且**同一次比對裡有另一塊
完全命中**,那就是相位。要確定,**去量幾何,不要繼續看像素** ——
`getBoundingClientRect()` 的小數點後三位一句話就講完了,而我在像素上繞了四輪。

### 4. 全寬的帶會把「對話框背後那一頁」一起比進去

11 是 `.overlay`,而底下那一頁在左右兩側是露出來的。用全寬的帶去比 `.who`,
量到的 5.7% 差異**大部分是背景那一頁**(那一頁真的變了)。
限定 `--x 60 720` 之後掉到 0.85%,而且最佳位移從錯的 `+34` 變成對的 `+33`。

> **這就是「工具量到的東西跟你要回答的問題不一樣」在這一輪的長法。**
> 它不報錯,只是給你一個乾淨的錯答案 —— 而且那個答案指向「凍住沒守住」。

### 5. 我自己把 `SRC=` 指到了 worktree 的**根目錄**而不是它的 `tokyo-trip/`

`cp -r "$SRC/." .work/` 於是複製了整個 repo,`.work/index.html` 不存在,
python 那一段丟例外,腳本在出處印完之後就停住 —— **而我第一次是用
`2>&1 | grep` 看輸出的,traceback 被 grep 濾掉了,看起來像「它印完出處就沒事了」。**
`shots/expform-pre-input/` 裡只有一個 `PROVENANCE.txt`,一張圖都沒有。

沒有修工具(使用者錯誤),但登記形狀:
**用 `| grep` 看一支會失敗的腳本,等於自己把錯誤訊息關掉。** 先看完整輸出。
