# 地點搜尋:打關鍵字、看候選、自己選一個

**Lulu 要的**:「流程會變成輸入去哪時,是用 google map 的搜尋在找,
確定找到就可以選取後加入,就像我們一般在 google map 搜地點那樣。」

**這一輪先用免費的 Nominatim 做介面**(她的決定)。資料來源之後可以換,
換的地方只有一個函式(`seekPlace`)。

---

## 它取代的是什麼

在這之前:使用者打一個字串 → **程式背地裡拿去查** → 猜中就標對、猜錯就標到四百公里外,
而他從頭到尾不知道發生過這件事。

那是「泡溫泉 → 鳥取的吉方温泉通り」和「港灣未來 → 福井的勝山丸岡線」的成因,
也是後來每一個補丁要處理的同一件事:硬界線(`863ee2a`／`14121ee`)、
`OUTSIDE` 人工表(`275da9b`)、虛線圈、「再查一次」(`7dc467c`)。

**讓人看著名字和地址自己挑,那件事整個不見。** 三間 teamLab 擺在他面前,
他知道要哪一間 —— 而那是任何服務、任何表都答不出來的。

---

## `bounded=1` 帶不帶,答案跟「誰在挑」綁在一起

`pinFor()` 帶,`seekPlace()` **不帶**。這不是不一致,是同一條原則的兩半:

| | 誰挑 | 框外的東西進來會怎樣 |
| --- | --- | --- |
| `pinFor()` | **程式**,挑完直接標上去 | 一顆沒有人看過的錯 pin → **要硬界線** |
| `seekPlace()` | **人**,看著名字和地址 | 多一列他不會按的候選 → **硬界線只會把他要的藏起來** |

`57473b5` 當初拆掉硬界線的理由是「它不會回答查無,只會從框內硬挑一個交差」——
**那個理由在有人看著的時候不成立**。viewbox 留著當加權(這趟在哪就偏重哪),沒有壞處。

> 順帶查到一件文件的事:`bounded=1` 的歷史是
> **加(`863ee2a`)→ 拆(`57473b5`)→ 又加回來(`14121ee`,改成每次查詢自己選框)**,
> 而 `DECISIONS.md` 的「改過主意的地方」那張表**只記到第二步**。
> 第三步在原始碼註解裡論證得很完整,但那張表是給「回溯時最常要找的線」用的。
> **`DECISIONS.md` 現在鎖在 ef 手上,這一筆要排隊補。**

## 人親手選的座標,必須贏過人工表

選完之後座標寫進 `pins[名字] = { la, lo, by:"pick" }`,**所以這一筆從此不會再被查**。

`by:"pick"` 不是裝飾,它擋的是**今天稍早自己加上去的那段對帳**:
開場會把「人工表答得出來的 key」一律換成表的值,而表比對的是**子字串** ——
使用者從候選清單裡挑的「箱根湯本站」會被 `箱根` 命中,
精確座標會被換成箱根那個概略的區域中心。

> **他看著名字和地址挑的東西,比任何表都更知道他要什麼。**
> 這正是 ADOPTION「加一條規則也要問它連帶關掉了誰」那一節的形狀 ——
> 只是這次那條規則是我自己四小時前加的,而被它關掉的是一個當時還不存在的功能。

探針兩筆對照:`箱根湯本站`(有 `by:"pick"`)對帳不碰,
`箱根神社`(沒有)照樣被表接管。

## 幾個刻意的選擇

| | |
| --- | --- |
| **按 Enter 或按鈕才查,不邊打邊查** | Nominatim 的使用條款是一秒一次(重用既有的 `queued()`);而且邊打邊查會把「東京」這種打到一半的字送出去。換成要錢的 Places 之後這件事會從禮貌變成帳單 |
| **Enter 不送出表單** | `preventDefault()`。在地點欄按 Enter 想搜尋,結果整筆行程被加進去,是很難回頭的那種錯 |
| **查無就說查無** | 「找不到。換個說法試試 —— 店名找不到的話打最近的車站或街區。」**不退而求其次給一個**,那正是這個功能要取代的行為 |
| **候選同時給名字和地址** | 光看名字分不出兩間同名的鬼太郎茶屋 —— 而分得出來正是要人挑的理由 |
| **空字串不發查詢** | 探針驗過:按了搜尋,`asked.length === 0` |

### 第 12 張:候選清單第一次有畫面

上一輪的 N2 登記著:「新提示量到了位置、尺寸、色值、字級,**但沒有任何一張截圖裡有它**」——
因為它預設 `hidden`,而「零差異」是那一輪的驗收條件,兩件事互斥。
**候選清單一模一樣**:預設 hidden,前十一張沒有一張拍得到。

所以這一輪補了 `12-place-search`,而且**樁裝在截圖腳本裡,這張圖不碰網路** ——
直接查的話它會變成「非決定性來源」那張表上的新一列。
回的三筆是真的(大阪／麻布台／京都三間 teamLab),那正是這個功能存在的理由。

### 探針自己有一個競態,而且它偽裝成「沒跑」

負向對照第一次回傳的是 `{說明:"非同步"}`,看起來像探針沒跑。實際上:

```
probe.sh:100  out = (function(){ …探針… })();
probe.sh:102  document.getElementById("r").textContent = JSON.stringify(out);
```

探針如果**同步**跑完(要量的東西不存在,第一個 `getElementById` 就 null 爆掉),
它寫的 `#r` 發生在外層那一行**之前**,然後被佔位值蓋掉。

> **修法是第一件事先 `await sleep(0)`。** 而教訓是:
> **「探針沒有回傳東西」和「探針回傳的東西被蓋掉」長得一模一樣**,
> 而後者只在它**該變紅的那棵樹上**發生 —— 也就是說,
> **這個 bug 只會在負向對照上出現,而負向對照正是用來證明斷言有效的那一步。**
> `geofix.js` 是同一個結構,只是它從來沒有快到會撞上。
