# 「想去哪」和「地點」合併成一欄

**Lulu 要的**:「把想去哪跟地點那兩欄合併。」

兩個決定是她做的:
- **只有挑過的才上地圖**（打了「泡溫泉」不會被拿去猜）
- **兩個表單都合併**（許願的「想去哪／地點」和加行程的「做什麼／地點」）

---

## 支點:不改地圖那條路,只改誰去填 `place`

「把自動猜測拿掉」聽起來要動地圖、天氣、人工表那一整串。**不用。**

**「沒有 `place` 就不查、不上地圖」是本來就在的規則**（規則一，`7dc467c`）。
所以只要讓 `place` **只有在使用者從候選清單挑過的時候才寫**，自動猜測就消失了：

```js
const place = locatedAt(title) ? title : "";
```

`locatedAt()` 問的是「這個字串在 `pins` 裡，而且是 `by:"pick"`」——
**而 `by:"pick"` 只有 `takeHit()` 寫得出來**，所以打字打不出一個假的已標定。
使用者挑完又去改字，查不到就自動回到沒標定，不必另外清狀態。

| | 以前 | 現在 |
| --- | --- | --- |
| 打「泡溫泉」 | 背地裡拿去查 → 鳥取的吉方温泉通り | **沒有 place、沒有查詢、沒有 pin**，並且當場講「還沒挑地點」 |
| 打「teamLab」再挑一間 | （沒有這條路） | place = 挑到的名字，座標跟著候選一起存下來 |

## 三個會咬人的地方

### 一、既有的 `place` 不可以被悄悄丟掉

地點欄從畫面上消失了。編輯一筆本來標好位置的行程時，如果照著「空欄位」寫回去，
**那一筆的位置就在使用者沒看到、沒同意的情況下不見了**。

所以編輯對話框有三種情況：

| | |
| --- | --- |
| 剛挑過 | 用挑的 |
| 沒挑、標題沒動 | **原來那個留著** |
| 標題改了又沒挑 | 清空（舊的 `place` 講的是舊的地方，留著會標錯） |

而且既有的位置**在狀態列上講出來**（`✓ 已標定 · <地址>`）——
合併如果讓它變成看不見，那就不是合併，是藏起來。

### 二、航班節點沒事，因為它根本不經過表單

`{ title:"桃園機場 第一航廈 報到", place:"樂桃 MM626 · 建議起飛前 2.5 小時" }` ——
這是 `title` 和 `place` 真的不同的那種資料，合併會壓扁它。

**查過:那種資料只活在寫死的 `ANCHORS` 裡，而 `ANCHORS` 不能編輯**
（`index.html:3082` 點它不會開對話框，`movable` 也排除它）。所以不受影響。
**這是動手前查的，不是事後發現的。**

### 三、文案要跟著畫面改

「補上地點就會出現」現在是在叫使用者去找一個**不存在的欄位**。
改成「按欄位旁邊的『搜尋』挑一個就會出現」。

## 對探針的衝擊：這不是改個選擇器

`geofix.js` 有八處在 `#wf-place` / `#sf-place` 上打字。**那兩個欄位不存在了，
而且不是改 id 就好——「打字打出一個 place」這件事本身被刪掉了**，
那正是這一輪的內容。

| 原本的測法 | 怎麼處理 |
| --- | --- |
| 在地點欄打字建立「有 place」的資料 | 改用 `pickPlace()`：搜尋並挑選。**量到的東西因此更接近真的** |
| 在地點欄清空建立「沒 place」的資料 | 直接刪掉那幾行 —— 沒挑就是沒有 |
| 「富士電視台掉到線上查詢」 | **判準換了**：現在沒挑就不會有任何查詢（規則一），所以改成問「表有沒有接住它」（沒接住＝沒有 pin） |
| 「查不到」那一段 | **拿掉，而且它不是搬走，是變成到不了**，見下 |

### 「查不到」變成只有舊資料到得了

送出時要有 `place` 只剩一條路：從候選清單挑一個——**而挑到的東西必定有座標**
（座標就是跟著候選一起來的）。所以「有 place 但查不到」這個狀態，
**在新增的那一刻再也產生不出來**。

那句話的程式留著，因為合併之前存下來的 place 在編輯送出時會走同一個
`checkPlace()`（`index.html:3256`）。但要測它得在 fixture 裡種一筆查不到的舊資料，
而那會多一項行程、改掉天數計數，**連帶動到 01 / 02 兩張截圖** ——
為了測一條 legacy 路徑去改基準，代價大於它買到的東西。登記在下面。

## 驗收

- **`probes/seek.js` 25 → 34 條全過**，新增的九條測的就是合併本身
  （挑過的 `place` 等於挑到的名字、沒挑的是空字串且零查詢、文案、編輯不丟位置）
- **`probes/geofix.js` 131 條全過**（原 133，拿掉「查不到」那兩條）
- **截圖：只有 05 / 08 / 09 / 12 變** —— 四個有表單的地方，其餘八張逐位元組相同

### 順帶發現：05 也是雙穩態的

連截三次，05 得到兩個值（一次 A、兩次 B），而 01 在同一三趟裡穩定不動。
`y=454..651`、1 群、2.68%，**位移搜尋兩個方向都說「對不上」** ——
但 `crop.py` 切出來一看就知道：那是**日期橫條捲到不同的水平位置**，
跟 01 登記的是同一個機制。

> **位移搜尋對捲動容器不成立。** 橫條捲動時邊緣會補進原本在畫面外的內容，
> 那一塊在另一張圖裡根本不存在，所以整條帶永遠對不齊。
> 那個工具是為「整片被往下推」設計的，不是為「視窗移動」。
> **工具說「不是位移」的時候，先問它有沒有能力回答這個問題。**

已經登記進「非決定性來源」，含判準和「為什麼它跟 01 的位移量對不上也不代表是新問題」。
