# 找地點收成一顆按鈕：三段式

**Lulu 問的**：「這個再查一次不就等於搜尋嗎？」

從使用者站的位置看，它們就是同一件事。我一開始只看到程式面的差別
（不同服務、一個免費一個付費、一個回多筆一個回一筆），**而那個差別對按按鈕的人不存在**。

## 真正的理由：它的前提消失了

「再查一次」存在的理由是「**程式自己猜錯了，換一家重猜**」。

而兩欄合併之後（`merge-place-field`），**程式不再自己猜** —— 沒挑就沒有 pin。
那個理由整個沒了，剩下的真實需求是「免費那家找不到，我想換一家再找」，
而那是搜尋流程裡的一步，不是另一個功能。

> **一個概念因為前提消失而退場，跟介面簡化長得像，但不是同一件事。**
> 後者常常會把有用的東西一起收掉；前者收得乾淨。

## 三段

| 第幾次按（沒挑到候選） | 畫面 | 問誰 |
| --- | --- | --- |
| 1 | 候選清單 | 免費（Nominatim） |
| 2 | ＋「試試加入車站或地點名」 | 免費 |
| 3 | ＋「還是沒有找到嗎？」按鈕變鮮明、字變**強力搜** | **下一按**才走 Google |

**第 3 段只換按鈕，不會自己去花錢。** 要錢的那一下永遠是使用者看著一顆
長得不一樣的按鈕、再按一次 —— 那是「要錢的動作藏在刻意的操作後面」在這個流程裡的落點。

**畫面上不講「改用 Google」**（Lulu 的決定）：使用者不需要知道背後換了哪一家。

**第 1 次不給提示** —— 那時候還沒有「找不到」這件事，提早講等於預設他會失敗。

**挑到候選就歸零**，每個表單打開也歸零。不歸零的話，下一個地方會從花錢那一段開場。

## 後端那道窄路拆了，而它不是壞掉

`wishAsksForItsOwnPlace`：沒有通行碼的人也能打 geocode，條件是
「**查的字串必須就是那筆願望已經存著的地點**」。它不驗身分（驗不了），
改成限制**被問的是什麼**。

**它跟搜尋根本不相容**：

> 那道檢查只在「被問的東西是資料庫裡已經有的」時成立，
> 而**搜尋的本質是問一個還沒存進去的字**。

所以合併之後它會把那三個沒有通行碼的人**每一次都擋掉** ——
而「免費那家找不到，換一家再找」正是這個功能存在的理由，擋掉等於把功能拿掉。
**不是參數調一調的問題。**

成本改由 Google 金鑰自己擋：**`v3 requests per day = 500`**（Lulu 設的）。
那是 Google 強制執行的硬上限，比我們寫任何程式都可靠 —— 超過就是 Google 拒絕，
不是她的卡被刷。以牌價每千次約 US$5 估，最壞一天約 US$2.5。

**剩下的風險是額度被故意用光**（那天大家都搜不了），不是帳單失控。她拍板接受。

## 那顆按鈕的三層條件，逐一交代去了哪裡

`wish-edit` 那一輪的 `#we-again` 有三層。協調者提醒「不能只搬前兩層」：

| 原本的條件 | 去了哪裡 |
| --- | --- |
| 有 place 才畫 | **不再需要**。第 3 段的觸發是「連找兩次沒挑到」，跟有沒有地點無關 |
| 人工表命中就不畫 | **刻意拿掉**。它講的是「拿存著的地點去重查」；第 3 段送的是使用者剛打的字，他明擺著在找別的東西 |
| 快照模式不畫 | **搬進 `paintSeekBtn()` 和 `runSeek()`**，兩邊都有 `!onSnapshot()` |

**第三層一定要跟著搬**：在一份凍結的副本上開一個花錢的動作，是 `wish-edit` 剛關上的門。

## 過程中三個錯，兩個是我的

### 一、我在網頁程式裡寫了 `d.querySelector`

`d` 是**探針的別名**，不是網頁裡的變數。於是 `seekBtn()` 一呼叫就拋例外，
查詢根本沒送出去 —— 而探針報的是「候選 0 筆」「按鈕沒變」，看起來像三段式的邏輯錯。

> **症狀出現的地方離原因很遠**，因為那個例外被 `runSeek()` 外面的 try 吃掉了。

### 二、我刪一段程式時多刪了 383 行

要拿掉 `#we-again` 的事件處理器，我用文字切割 —— 而 `rindex("  });")`
找到的是**整段最後一個**，不是那個 handler 的結尾。**抽屜、地圖開關、登入、匯出
全部跟著不見了**，而 `new Function` 的語法檢查**照樣通過**（刪掉完整的函式不會有語法錯）。

症狀是四支探針同時大面積退化、連「抽屜打得開」都紅。

> **語法檢查不會告訴你刪掉了什麼。** 用文字切割改程式的時候，
> 檢查的對象應該是「改動的行數是不是我預期的量」，不是「它還編得過嗎」。
> 這次 `git diff --stat` 一眼就看得出來（+123/−44 vs −383）。

### 三、我拿了過期的基準（第三次了）

`shots/we-final` 是 `be3e0ef` 截的，**而抽屜的修正在 `18b7525` 才合進來**。
於是 07 顯示差 14.5%，我花了四次量測（含兩個方向的位移搜尋）才發現是基準比程式舊。

對的基準是 `shots/snapguard`（`18b7525`）。**判準應該先看 `PROVENANCE.txt` 的 HEAD
是不是我要比的那個 commit**，而不是看哪一組時間最近。

## 沒有驗到的

| | |
| --- | --- |
| **Google 真的回什麼** | 探針是樁。量到的是「伺服器照規格回 X 的時候前端做了什麼」 |
| **第 3 段在真人手上的節奏** | 「連按兩次沒挑到」在合成事件裡是瞬間的，真人中間會讀、會改字、會猶豫。**那個節奏只有她試得出來** |
| **額度用完長什麼樣** | 文案寫了（「可能是今天的查詢次數用完了」），但**沒有人看過**，要真的打爆 500 次才會出現 |
